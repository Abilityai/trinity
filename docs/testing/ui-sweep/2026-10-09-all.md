## 2. Critical

### 🔴 C-1 — Anonymous public-chat history never restores after reload (session id lowercased on lookup)   `fp=d4a6e8df`   `functional`   #3443

**Repro**
1. Create a public link on an agent whose access policy has the email gate off.
2. Open `/chat/<token>` logged out (1440, light) and send one message.
3. Reload the page.

**Expected:** The visitor's conversation is restored after a reload ("Refresh keeps place").

**Observed:** The empty "Start a Conversation" state. `GET /api/public/history/<token>?session_id=<id>` returns 200 with `{"messages":[],"message_count":0}`; the client sends the stored id with its case intact.

**Validated:** source — `src/backend/db/public_chat.py:146` — the lookup compares `session_identifier == session_identifier.lower()` unconditionally, while the create path (line 84) lowercases only when `identifier_type == 'email'`, so a mixed-case anonymous token never matches its own row.

**Evidence:** `evidence/2026-10-09-all/d4a6e8df-1.png`
