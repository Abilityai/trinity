# CSO Audit — 2026-07-14 (diff mode, `feature/1595-agent-git-gc`)

Scope: branch diff vs `dev` merge-base (#1595 — survivable git maintenance).
Mode: daily (8/10 confidence gate), `--diff`. Phases 0–2, 5–7, 9 (delta), 12–14;
Phases 3–4 no-op (no dependency or workflow changes in diff).

## Attack-surface delta

- **No new HTTP endpoints.** Three existing agent-server endpoints
  (`/api/git/sync`, `/api/git/pull`, reset) gain a 409 `agent_busy` contention
  path (repo lock) — behavior change, no new auth surface (all behind the
  #1159 agent-token middleware).
- **New agent→backend data flow**: `pack_count` / `loose_objects` /
  `maintenance_failures` ride the agent-writable `sync-state.json` →
  `/api/git/status` → `agent_sync_state` → sync-health API. Coerced at the
  backend boundary (`_coerce_nonneg_int`: int-only, bool-rejected, range-capped).
- **New operator-queue item type** `git_bloat` — server-composed text + coerced
  ints only; no agent-controlled strings.
- **New env knobs** (operator-set): `GIT_MAINTENANCE_TIMEOUT_SECONDS`,
  `GIT_MAINTENANCE_LOOSE_THRESHOLD`, `GIT_DIR_ALERT_BYTES`.
- **File deletions** (agent-side hygiene): fixed paths/globs under the agent's
  own `.git`, same UID, age-gated — no privilege boundary crossed; `unlink` on
  a symlink removes the link, not the target.
- **Sweep-allowlist widening**: `run_registered` registers transient PIDs —
  TTL-bounded, finally-paired, in-process only (agent code cannot call it).

**Exploit scenario for #1 (why HIGH):** on a shared instance, a user with
shared (non-owner) access to an agent can read `GET /api/agents/sync-health`;
after any failed push (auth error, collision) the summary carried the agent's
GitHub PAT — privilege escalation from "can view agent" to "can write the
agent's GitHub repo". Exposure decays for `last_error_summary` (single row,
overwritten each poll) but `operator_queue` collision rows persist ≤90 days.

**Ops advisory (follow-up, not a code change):** instances that saw failed
pushes before this fix may hold PATs in retained `operator_queue` rows —
recommend a one-time scan/scrub and opportunistic PAT rotation on shared
fleets (trinity-ops runbook material).
