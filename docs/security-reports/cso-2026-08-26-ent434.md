## Verified-safe (cited, not assumed)

Each of these was a plausible finding that was checked and refuted with evidence:

1. **Route shadowing (Invariant #4).** `PUT /settings/headroom-alert-threshold` is two
   segments; the only parameterized PUT declared before it is `/agents/{agent_name}`,
   whose literal first segment differs. No `PUT /{subscription_id}` exists. Not shadowed.
2. **The catch-all validation change cannot 500.** `body.value = validate_ops_setting(...)`
   requires a mutable model: `db_models.SystemSettingUpdate` is a plain `BaseModel` (not
   frozen) — proven by executing the assignment in the running backend. The function is
   `-> str` and normalises `'  90 '` → `'90'`, the same type `db.set_setting` already
   received, so no downstream reader changes behaviour. **This is a strict tightening**:
   20 ops keys previously accepted `"abc"` / `"-40"` verbatim through this route and now
   return 422.
3. **Alert payload carries no secret material (canary G-04).** Context is ids, names,
   percentages, timestamps, counts and booleans only. No provider response body, no
   snapshot object, no exception text. The single `logger.exception` logs the item id.
4. **Agent names in the alert body are sanitized.** They arrive via
   `db.get_agents_by_subscription` from `agent_ownership`, written through
   `sanitize_agent_name` (Docker naming charset), and are capped at five per alert.
5. **Redis `ping()` on an async route is bounded.** `get_breaker_redis` builds its client
   with `socket_connect_timeout=1, socket_timeout=1`, so the new settings-read status probe
   cannot stall the event loop beyond 1s.
6. **Admin gate is the current one.** Both new/extended routes use `assert_admin`, which
   since #1890/#2323 rejects agent principals and enforces the `ADMIN_GATE_SCOPES`
   allowlist — an agent-scoped MCP key resolving to an admin owner cannot reach them.
7. **Reserved-prefix guard is in place.** `sub-headroom-` is registered in
   `_RESERVED_ID_PREFIXES`, so an agent cannot pre-create the deterministic id and use
   `ON CONFLICT DO NOTHING` to silence its own alarm.

## Cost amplification (the one DoS class in scope)

The sampler probes the operator's own quota, so it is assessed rather than excluded.
Bounded and quantified: ~24 probes/day/subscription (`SAMPLE_INTERVAL_SECONDS` 3600,
floored at `REFRESH_SECONDS`), each a `max_tokens=1` Haiku call — **4x less than a
watched instance already spends** through the 900s ambient refresh. The interval is a
constant, not an operator knob (#1644), it inherits #471's 60s per-subscription floor and
single-flight lock, it is gated on the existing `subscription_headroom_auto_refresh`
toggle, and it stops entirely at `threshold_pct = 0` (pinned by test). Per-cycle alert
emission is capped at 5. **Not a finding.**
