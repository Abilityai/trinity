**Verified clean** (evidence-based, not assumed):
- **Secrets (P2)**: 0 secret-prefix matches across all branch commits (`git log -p` scan, word-anchored). The spike's setup token was read in-memory from a container inspect during planning and never entered the repo, argv, or logs; test fixtures carry only utilization numbers.
- **Credential handling (P7)**: the probe's two log sites emit `type(e).__name__` + subscription id only; the token appears solely in the Authorization header of one fixed-URL request; error bodies are not echoed into responses. `GET /settings/headroom-auto-refresh` returns booleans/intervals only.
- **SSRF (A10)**: no user input reaches the probe URL — the endpoint resolves the target from a hardcoded constant; the subscription is chosen by id from the DB, never by caller-supplied URL.
- **Access control (A01)**: quota-spending actions (refresh, toggle) are admin-only; the pressure payload discloses `subscription_name` only to accessors of the agent, matching the existing `AgentAuthStatus` gate (`assert_agent_access`) — no widening of the fleet-roster surface (the operator's out-of-scope ruling holds). No enumeration oracle: the batch endpoint takes no per-agent parameter and admin-only routes have no differential to leak.
- **Injection (A03)**: all new queries are SQLAlchemy Core with bound parameters; no subprocess, no template rendering; no `v-html` in any changed Vue file.
- **Supply chain (P3)**: zero dependency, workflow, or Dockerfile changes.
- **Cost/abuse (P7)**: probe spend is bounded by design — 60s floor per subscription (click), 15-min floor + default-ON-but-toggleable ambient, single-flighted, fail-closed without Redis (pinned by `test_unreachable_redis_never_ambient_probes`). Non-admin dashboard polls can *drive* ambient refresh of subscriptions funding their accessible agents — bounded by the same floors and explicitly accepted at the build gate (operator ruling, default-ON).

**Notes below the gate** (LOW, recorded for completeness):
1. The generic `PUT /api/settings/{key}` catch-all can write `subscription_headroom_auto_refresh` without validation; any non-"true" value reads as OFF — the failure direction is *less* probing, i.e. safe. Not blocklisted like the retention keys because the blast radius is nil.
2. The probe sends a Claude-Code-style User-Agent (the POC's working recipe; the endpoint rate-limits unfamiliar agents). Operational fingerprinting choice, documented in the service docstring — not a vulnerability.
3. `error_message` on failure events remains unexposed by all new read surfaces (counts and kinds only) — the G-04 discipline holds; the column itself predates this diff.

## STRIDE (new component: headroom probe service)

- **Spoofing**: probe authenticates outbound with the operator's own token; inbound triggers are admin-JWT or scoped-poll gated — no new identity surface.
- **Tampering**: snapshots live in ACL'd Redis on the platform network (agents physically cannot reach it, #589); a tampered snapshot could at worst mislabel pressure — it never gates execution.
- **Repudiation**: toggle writes log the actor; probe refreshes log at DEBUG with subscription name.
- **Info disclosure**: readings are utilization percentages + reset times — telemetry, not secrets; scoped per the access rules above.
- **DoS**: floors + single-flight + fail-closed Redis rule bound probe volume; the batch endpoint serves stale-while-revalidate so a hung provider cannot wedge the dashboard poll (pinned).
- **Elevation**: none — no new write paths to platform state beyond the admin toggle.

## Verdict

**PASS for merge.** Zero findings at or above the daily 8/10 gate. Two structural risks found and fixed during the pre-landing `/review` (fail-closed Redis tri-state; stale-while-revalidate on the poll path) are regression-pinned in `tests/unit/test_471_subscription_usage_observability.py`.
