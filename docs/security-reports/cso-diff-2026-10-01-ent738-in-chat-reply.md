## Architecture (Phase 0)

Until this change, a person could reply to one message only from the Inbox pane. This change adds a second way in: a Reply button in each persisted agent message's action row inside the 1:1 Workspace chat. It is frontend only.

- **The button.** `PortalAgentBubble` renders Reply when the host passes a `replyLabel`, and emits `reply`.
- **The target.** `PortalConversation` builds `{sessionId: currentSessionId, messageId, excerpt}`. The excerpt is a one-line display string derived client-side from text already on screen. The shell (`Portal.vue::setReplyTarget`) holds it as the same `replyTarget` the Inbox path already sets.
- **The chip.** The composer chip renders the excerpt by interpolation.
- **Clearing it.** Escape clears the chip through `resolveComposerKey`'s new `drop-reply` result, and so does a conversation switch (`watch(convKey)`).
- **The send.** It still carries only `reply_to_message_id`. It is unchanged.

The trust boundary is unchanged. The client chooses an id, and the server proves it in `client_portal/service.py::reply_context` before anything is written. The id must belong to this caller (email), this agent and this thread, or the server returns one uniform 422. The quote the agent sees is built server-side from the stored row and framed (`[Client Portal] The user is replying to …`, `> `-quoted, capped at 2000 characters). The client cannot supply quoted text.
