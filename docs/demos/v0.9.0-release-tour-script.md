# Trinity v0.9.0 — Release Tour video script

Format: screen recording of the real Ability.ai fleet, narrated. Two audiences at
once — people who have never seen Trinity (explain *what it is* as you go) and
existing users (show *what's new*). ~15–18 min. ★ = must-show.

Open on the Grid dashboard with the org overlay; the fleet **is** the explanation.

---

## 0. Cold open — the fleet as an org chart (2 min) ★

**Show:** Dashboard → Grid view, org overlay ON — department zones + reporting lines
over the live agent tiles (ent#305). Pan/zoom. Hover a tile: live status, activity
sparkline, cost + completion, inline Run/Auto toggles.

**Say (what Trinity is):**
- "This is the multi-agent system that runs our company. Every tile is an
  autonomous AI agent — its own isolated Docker container, on our own hardware."
- "Trinity is the platform underneath: it deploys them, schedules them, lets them
  delegate to each other, and audits everything they do. Claude Code writes the
  agent; Trinity runs it in production."
- Point at a department zone → "departments and reporting lines are just tags —
  no schema, and the reporting lines are real delegation permissions."

**Then:** Tiles menu → add the two new **data tiles**: *Executions by trigger*
(24h) and *Recent failures* (ent#325/#96/#100). Note the scanline loading motion.
Switch to **List view** (ent#260) → hit `/` and type-to-filter (ent#261) → back to
Grid. Also `?` — mention the Timeline mode exists.

---

## 1. Inside one agent (2 min)

**Show:** click one agent → Agent Detail **Overview** (trend charts, health,
compatibility panel). Tabs strip: Schedules, Skills, A2A, Git, Access, Loops.

**Say:** "Each agent has a template repo on GitHub, a `CLAUDE.md`, skills, cron
schedules, credentials injected as files, and a persistent workspace volume."
- Schedules tab: a cron schedule + its execution history / analytics.
- **Skills tab** (ent#235): assigned skills + injection status. "Skills are the
  unit of capability; more on that in a minute."
- Agent **MCP key** panel (#1854): "every agent gets its own scoped key into
  Trinity — this is how they talk to the platform and to each other; you can
  verify it against the container and rotate it."

---

## 2. Workspace — the client-facing surface (4 min) ★ headline

**Say:** "Until now Trinity was an operator console. v0.9.0 adds **Workspace**:
the surface for the *people your agents serve* — clients, colleagues, customers —
and it's in every build, OSS included."

**Show, in this order:**
1. **One-click open** from the nav (ent#357) → same session, no second login.
2. **Sidebar** (ent#359): agents on top, starred chats, dated chats.
3. **Agent page** (ent#360): click an agent → its overview, recent work, and
   **Reports** rendered properly (table / KPI / markdown, not raw JSON — #2162).
4. **New chat** → the **briefing hints** ("things you can ask", ent#380). Click one
   → it *pre-fills* the composer, doesn't send.
5. **Composer typeahead** (ent#392): type `/` → the agent's playbooks; `@` →
   reachable agents.
6. **Send a real task** → **streaming** tool activity live in the chat (ent#286).
7. **Multi-agent chat** (ent#361/#362 — entitled build): new chat with two agents;
   then from a 1:1 chat `@mention` a third agent → it joins mid-conversation.
8. **Voice** (30 s): mic dictation + a spoken reply on a voice-enabled agent
   (#2212/#2157).
9. **External client path**: log out, sign in with only an email code — no Trinity
   account (ent#281 sign-out, ent#375 sessions don't expire at 12 h).

**Say:** "Behind it: verified-email access, per-client rate limits, sessions that
survive, sign-out that actually signs out. Operators still see everything in the
console."

---

## 3. How this fleet was provisioned — from zero (4 min) ★

**Say:** "Now rewind — how do you get a fleet like this? v0.9.0's other big theme
is fresh-install provisioning."

**Show:**
1. **Library** page (ent#263): tabs **Agent Templates · Systems · Skills**.
2. **Remote template registry** (ent#14): the catalog is fetched from a
   registry repo — Settings → Template Registry status. One line: "air-gapped?
   `TEMPLATE_REGISTRY_ENABLED=false`."
3. **GitHub-repo import wizard** (ent#15): paste a public repo URL → fork / copy /
   clone-own → inline compatibility check → create. Emphasise: **no PAT needed
   for a public repo**.
4. **Guided credential setup** (ent#127/#128): the new agent's per-variable
   checklist — set / missing, and "how to get" links from `template.yaml`.
5. **Install a system from a manifest** (ent#126): Systems tab → pick a bundled
   manifest → **dry-run preview** (agents, permission topology, schedules) →
   Deploy → land on the Dashboard filtered to the new fleet.
6. **Bind to your own repo** (ent#109): Git tab of a tokenless agent → bind to a
   repo you own → "your agent's accumulated work is now yours, in your GitHub."

---

## 4. Skills platform (2 min) ★

**Show:** Library → **Skills tab** (ent#384): every skill with the agents that
hold it; sources = the bundled **community repo** + your own repos (ent#237,
tag-pinned). Agent Detail → Skills → assign one → injection status.

**Say:** "One skill model: distribute from a library, place on an agent, expose
to the outside. Scheduled auto-sync and fleet-wide re-inject (ent#236) mean a
skill update reaches every agent without touching them."

---

## 5. Agents talking outward (2.5 min)

- **Reports** (Epic #1534): an agent publishes a report → it appears on the
  dashboard/Operations → **export to Excel/PDF** (#1536), search/filter (#1539);
  agents can read their own reports back over MCP (#1538).
- **A2A, bidirectional**: Agent Detail → **A2A tab** (ent#158) — toggle exposure,
  copy the Agent Card URL, curate exposed skills, inbound allow-list. Settings →
  A2A endpoints registry → `call_a2a_agent` to an external agent (#736).
  "Trinity agents are now first-class citizens of the A2A world — inbound and
  outbound."
- **Telegram** (phone recording, 30 s): 👀 reaction + elapsed-time placeholder
  while a task runs (ent#264); a long task **reports back** to the originating
  chat when it finishes (ent#265).

---

## 6. Ops & security — one screen each, no demo (1.5 min)

- **Automatic DB backups** (#2216): Settings → Retention → the backup block
  (last success, artifact count). "SQLite and Postgres, nightly, plus a
  pre-migration copy at boot."
- **Bounded container logs** (#1871) — "the disk-full class is gone."
- **Image upgrades propagate** (#1809/#1860/#1816): rebuild the base image →
  stop/start or Restart All actually adopts it.
- **Canary run-state** (#2217) + the harness now runs on prod compose.
- **Security slide**: admin gates reject agent keys (ent#297), hardened YAML
  everywhere, per-spawn credential env so a removed key stops reaching agents
  (#1999), portal sign-in brute-force protection, agent MCP-key verify/rotate.
