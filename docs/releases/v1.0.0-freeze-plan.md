### Release notes: Known limitations block (draft; public-safe)

```markdown
## Known limitations

- **Recreate agents on the 1.0 base image.** Agents still on an older image keep working,
  but the operator-queue write protection and the in-container skill-approval hook only
  take effect after the agent is recreated on the 1.0 image (the Skills tab shows a
  gated skill as "not enforced" until then).
- **Approvals have a single approver.** Approval chains and edit-before-approve are
  not in 1.0.
- **Self-change permissions** govern the changes an agent makes through the platform
  (skills, schedules, instructions, other agents). Edits an agent makes to its own files
  inside its container are not gated in 1.0.
- **Cross-instance agent-to-agent calls use keys.** Calling an agent on another Trinity
  instance requires an A2A key; network-trust (keyless) calling is not part of 1.0.
- **Pull dispatch is an opt-in pilot** per agent; push dispatch remains the default.
- **Sharing an agent gives that person full access to the agent's files.** Share only
  with people you trust.
- **PostgreSQL installs:** the seeded admin's sign-in email reads "admin" until you set a
  real address in Settings (abilityai/trinity#3554). The PostgreSQL role must be allowed
  to `CREATE EXTENSION pg_trgm` (execution search indexes).
- **DigitalOcean 1-Click** can be deployed on plans below the 4 GB / 2 vCPU minimum —
  choose at least that size (abilityai/trinity#3009).
- **Workspace:** a background run's card in the Work panel cuts off long outcomes
  (abilityai/trinity#3523); "Bind to this repo" stays disabled while the saved personal
  GitHub token is in use — bind via the API meanwhile (abilityai/trinity#3546).
- <if S1 drops> The role card can read "no assignment recorded" for the agent's primary
  and approver; the Access tab shows the correct seat (abilityai/trinity#3660).
- <if any ent#847 row is still ⬜/🟡 at the cut> Untested in this release: <rows>.
```

### Release notes: Upgrade notes block (draft; public-safe)

```markdown
## Upgrading from 0.9.5 — behaviour that changes by default

- **Hosted compose now defaults to the bundled PostgreSQL.** `start.sh --hosted` keeps an
  existing SQLite install on SQLite. If you run `docker-compose.hosted.yml` directly and
  your data is in `trinity.db`, add `DATABASE_URL=` (empty) to `.env` before upgrading, or
  migrate first (docs/migrations/SQLITE_TO_POSTGRES.md). `POSTGRES_PASSWORD` is now required.
- **Platform role `user` is Workspace-only.** See docs/migrations/WORKSPACE_ONLY_USER_ROLE_2026-10.md.
- **Agents can no longer change skills by default.** An admin grants "manage skills" per
  agent in Agent Settings.
- **Delegated work reports back.** When an agent hands work to another agent from a Slack,
  Telegram or Workspace conversation, the outcome is posted back into that conversation.
  Turn off with `MCP_REPORT_BACK_ENABLED=false`.
- **Telegram group context is on for existing groups.** Where the bot can read all group
  messages, untagged messages are kept and recent group history is given to the agent when
  it is tagged. Turn off per group in the agent's Telegram panel.
- **Pull sync starts on auto-syncing agents.** Agents with auto-sync on now also fetch and
  rebase from their remote on a timer.
- **New default limits:** inter-agent chain depth 8, event-triggered runs 120/hour per
  agent pair, pending asks marked aged after 24h, metric points kept 365 days
  (100,000 per agent per day). All adjustable in Settings → Ops.
```
