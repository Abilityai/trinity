## Highlights

1.0 is built around one story: **an agent takes a seat on the team.** It has a named
role, serves named people, works inside projects, is bounded by approvals the platform
enforces, is measured against business numbers, and reaches people through one Inbox.

- **Agents are assigned to people.** An admin names who an agent serves (its primary),
  who approves for it, who collaborates and who views; the agent knows this on every
  run. One companion can serve several seats, an agent can hold a seat itself, and every
  assignment change is audited. Workspace shows each person a **role card** with the
  role, objectives and metric freshness (ent#500, ent#527, ent#810, ent#811, ent#814,
  ent#817, ent#676).
- **One Inbox, platform-native approvals.** Workspace opens on an Inbox (Action / Unread /
  All, reading pane) across every agent. Agents ask over MCP; an ask can be answered with
  an option, "something else", discussed in a linked chat, or dismissed, and stays attached
  to the chat it was raised in. Asks are addressed to a **role**, never a named person
  (ent#610 in part, ent#611, ent#606, ent#816, ent#748, ent#747, ent#738, #2915, #3242,
  #3243, #3247).
- **Gated skills.** Mark a skill *requires approval by role X*: the approval reaches a
  person who can open the agent **before the agent ever sees the request**, an approved
  run executes once with exactly the approved input, and an in-container hook refuses the
  bypass lane. The requester is told how it ended (ent#751–#756, ent#844, ent#881,
  #3653, #3654).
- **Self-change grants and agent reach.** An agent changes its own skills, schedules,
  instructions, other agents or projects only with an admin-granted toggle. An agent key
  reaches only itself, the agents it may call and the agents it spawned — on fleet routes
  too; an edge exposes the skills the target declares, and library skills need a per-skill
  grant (ent#164, ent#756, ent#662).
- **Projects.** A project is a platform record with members, visibility, a Continue card,
  Tasks / Log / Files tabs and a Steward agent; agents work on projects over MCP
  (ent#661, ent#896, ent#588).
- **Business metrics and objectives.** Templates declare metrics; agents push points over
  MCP (batched, idempotent, restatements reported); dashboards and the role card show
  target vs actual with freshness, and a stale metric says so (ent#477–#479, ent#666,
  ent#812, ent#727, ent#729–#731, ent#671).
- **Suggestions and readiness.** "Things you can ask" and "Suggested for you"; a companion
  stays in `calibrating` (no proactive brief) until its owner marks it ready
  (ent#465, ent#637, ent#663, ent#689).
- **One Settings home per agent** and a restored **agent header** — in-place name and avatar,
  funding switcher, live sparklines, 7-day spend, GitHub line, capacity bars; a two-pane
  New agent dialog (ent#887, ent#888, ent#890, ent#891, ent#353, ent#950, ent#955, #3792).
- **Git sync that pulls.** Auto-syncing agents fetch and rebase on a heartbeat; conflicts
  are recorded; divergence over 24h turns red on the agent card and fleet health
  (ent#703–#708, #3010, #3011).
- **Workspace-only users.** Platform role `user` signs in to Workspace only; sharing an
  agent no longer creates an operator login (ent#837).
- **Hosting.** Hosted compose ships a bundled PostgreSQL; AWS one-click (AMI +
  CloudFormation) and a Vultr Marketplace listing join DigitalOcean (#3159, #3004, #2282).
- **A2A.** Outbound A2A is OSS core, x402-priced inbound A2A, and every inbound call now
  needs a credential (the keyless trusted-network path was removed before release,
  ent#885). Signed AAuth agent identity between instances ships **dark** behind
  `AAUTH_ENABLED` (PRs #2956, #3659).
- **Security sweep.** 81 security-themed issues across both trackers: agent keys can no
  longer act as their owner on admin/owner routes, guardrail hooks run from an isolated
  read-only config, the Files surface has one tier-per-verb rule, rooms re-check access at
  wake time, suspended accounts lose `/ws/events`, A2A callers see only their own tasks.

## ⚠️ Behavior changes / upgrade notes

### Rebuild or pull the platform images, then rebuild the agent base image and recreate agents

Agents on an older image keep working, but the operator-queue write protection and the
in-container skill-approval hook only take effect after the agent is recreated on the 1.0
image. Until then the Skills tab shows a gated skill as "not enforced".

### Behaviour that changes by default

- **Hosted compose now defaults to the bundled PostgreSQL** (#3159). `start.sh --hosted` keeps
  an existing SQLite install on SQLite. If you run `docker-compose.hosted.yml` directly and your
  data is in `trinity.db`, add `DATABASE_URL=` (empty) to `.env` before upgrading, or migrate
  first ([SQLITE_TO_POSTGRES.md](../migrations/SQLITE_TO_POSTGRES.md)). `POSTGRES_PASSWORD` is now
  required there. The PostgreSQL role must be allowed to `CREATE EXTENSION pg_trgm`.
- **Platform role `user` is Workspace-only** (ent#837). See
  [WORKSPACE_ONLY_USER_ROLE_2026-10.md](../migrations/WORKSPACE_ONLY_USER_ROLE_2026-10.md).
- **Agents can no longer change skills by default.** An admin grants "Change skills" per agent
  under Settings → Guardrails.
- **An agent can no longer run another agent's library skills by default** (ent#662). A
  permission between agents covers the skills the target declares itself; a library skill needs
  a grant per skill. Settings → Agents lists the calls from the last 30 days that are now refused,
  each with a Grant button.
- **Every inbound A2A call needs a credential** (ent#885). The trusted-network list now only
  limits where your agents may call out to.
- **Delegated work reports back** into the Slack, Telegram or Workspace conversation that asked
  for it. Turn off with `MCP_REPORT_BACK_ENABLED=false`.
- **Telegram group context is on for existing groups** (ent#600). Turn off per group in the
  agent's Telegram panel.
- **Pull sync starts on auto-syncing agents** — they also fetch and rebase on a timer.
- **New default limits:** inter-agent chain depth 8, event-triggered runs 120/hour per agent
  pair, pending asks marked aged after 24h, metric points kept 365 days (100,000 per agent per
  day). All adjustable via `PUT /api/settings/ops/config` (Settings → Ops).
- **Re-login** after the backend restarts and **reconnect** MCP clients.

### Config keys whose behaviour changed

Every `.env` / `docker-compose*.yml` key whose meaning changed between v0.9.5 and v1.0.0 (#3763):

- `DATABASE_URL` (hosted compose) — **unset now means the bundled PostgreSQL**; previously unset meant SQLite. Set it empty (`DATABASE_URL=`) to stay on SQLite. Prod and dev compose are unchanged (unset → SQLite).
- `POSTGRES_PASSWORD` — **required** by `docker-compose.hosted.yml` (the file does not render without it); previously only with `--profile postgres`.
- `ADMIN_PASSWORD_SOURCE` — new value `instance-id` (AWS image): `/setup` also asks for the EC2 instance ID (#3004).

- `TRINITY_DEFAULT_SKILL_SOURCE_REF` — default moves `v0.2.0` → `v0.5.0` (fresh installs only; existing installs keep their pin).
- `OPERATOR_QUEUE_TITLE_MAX` — still the truncate-with-marker cap, but agent-raised ask titles are now refused or held first at `OPERATOR_QUEUE_ASK_TITLE_MAX_CHARS` (120).

- **Approvals have a single approver.** Approval chains and edit-before-approve are not in 1.0.
- **Self-change permissions** govern the changes an agent makes through the platform (skills,
  schedules, instructions, other agents). Edits an agent makes to its own files inside its
  container are not gated in 1.0.
- **Signed agent identity between instances ships switched off.** Cross-instance A2A uses keys
  unless an admin enables AAuth; person tokens and resource calls are prototypes behind a second switch.
- **Pull dispatch is an opt-in pilot** per agent; push dispatch remains the default.
- **Sharing an agent gives that person full access to the agent's files.** Share only with people you trust.
- **DigitalOcean 1-Click** can be deployed on plans below the 4 GB / 2 vCPU minimum — choose at
  least that size (#3009).
- **Workspace:** a background run's card in the Work panel cuts off long outcomes (#3523);
  "Bind to this repo" stays disabled while the saved personal GitHub token is in use — bind via
  the API meanwhile (#3546).
- **The Workspace Inbox** ships six of eight planned pieces; room events in Unread and
  queued/running item state follow (ent#610 stays open).
- **Post-rc4 payload:** the release is cut from the `dev` tip, which carries ~80 commits after
  rc4 (agent header and Settings home, ent#662 skill grants, late security fixes). Those are
  covered by CI and the dev-instance deploy, not by an RC test pass.
