## 2026-09-21 — pitfall — An id the agent types is evidence of a CONVERSATION, never of a person; and a per-conversation identity column is not a per-speaker one
**Context**: trinity-enterprise#549 (a shared file is for the person the turn was for). Third occurrence of the 2026-08-21 class — a table scoped by an owning entity gains a per-person dimension (asks, reports, now files) — and the reader-narrowing half was routine. The half that was not: deciding WHICH turn an MCP tool call came from. The call carries the agent's key and nothing about the turn, so the only link is an `execution_id` the agent types, and on the reporter's own repro the agent cited the id of a turn 22 minutes old: a resumed Claude session copies ids out of its history even though each turn's prompt carries a fresh one. Four successive designs were each wrong in a way only a fresh-context reviewer or a live row showed. (1) *Trust the typed id* — passes a two-account repro, wrong in a room. (2) *The agent has exactly one running turn, take it* — OVER-shares: a web-terminal `claude` session holds the agent's key, has no execution row and cites nothing, so the rule lists an operator's file for whichever client is mid-conversation. (3) *A cited RUNNING row is the turn* — believes a zombie row a crash left `running` in a room beside someone else's live turn. (4) *`source_channel_agent != executing agent`* as the agent-to-agent tell — misses a self-task and A→B→A, where the two are equal. Separately, `source_user_email` on a channel turn is `verified_email OR the channel-native id`, and in a GROUP the verified email is the UNLOCKER's, set once per group; the per-user memory feature already refused group mode for exactly that reason, in a code comment nobody grepped for.
**Lesson**: (1) Treat an agent-typed id as proof of a *conversation* at most, and take the *person* from platform-written state about what is running in that conversation NOW; require the running direct turns to AGREE, and let every "could not tell" fall to the narrowest audience — the failure direction is then under-share by construction. State the residual (a session that carries another conversation's history) rather than implying it away; the structural fix is a platform-injected id (#2392 — `TRINITY_EXECUTION_ID` is already in every headless turn's process env). (2) "There is a single X, so it is ours" is sound only when every caller that can reach the code HAS an X: enumerate the callers without one (terminal, cron, an owner calling REST) before writing the shortcut. (3) A column written by exactly one path means "that path happened" — test it for PRESENCE, never against a value that same path can also produce. (4) Before reading an identity column on a new path, find who WRITES it and ask what it holds in the multi-party case (group, room, thread). Per-conversation is not per-speaker, and the fix is to have the writer state the fact where it knows it — the router stamping `source_channel_client` only for a verified one-to-one speaker — not to re-derive it downstream from id shapes. (5) The mutation battery is what found the vacuous test: `column == None` compiles to `IS NULL`, so "an unidentifiable viewer matches nothing" passed against an EMPTY table whatever the query said — seed both kinds of row before asserting an empty result, and assert the seed. And every `platform=True` read in the suite was the OWNER, so `include_owner_only=bool(is_platform)` — the exact over-share the change exists to prevent — survived until a non-owner platform viewer existed. When a guard has two inputs, the suite needs a row where they DIFFER.
