## 2026-11-03 — pitfall — A generation check goes stale across every `await` that follows it
**Context**: trinity-enterprise#1087, `DirectBridge._speak_sentence` (`src/backend/services/direct_voice_service.py`). The loop checked `generation != self._generation` once per chunk, then awaited a `spoken` send, then sent `audio`. An `interrupt` frame handled on the same event loop during that first await bumped the generation and queued its `audio_flush` on the send lock, so the stale chunk went out after the flush. The browser rebuilt its closed AudioContext on `play()` and the agent kept talking for one chunk after Stop. The existing test (`test_interrupt_drops_what_is_queued_and_old_speech_cannot_play`) passed throughout, because it bumped the generation before the call started rather than during an await inside it.
**Lesson**: In asyncio code, a cancellation or generation check protects only the statement right after it, up to the next `await`. Re-check immediately before every side effect that follows an await, not once per loop iteration. A test for this class must deliver the interrupt during the await: a fake socket whose `send_json` schedules the interrupt as a task and yields (`tests/unit/test_ent1087_direct_call_interrupt.py`). Never `await` the handler inline from inside `send_json`. The bridge's own send lock deadlocks on it.
