## 2026-10-07 — pitfall — A text gate must match every form the model can read, not one normalisation of it
**Context**: trinity#3274, `utils/skill_invocation.py` and `skill_gate_service.requester_context_text`. Widening the matcher's invisible-character set looked like a strict gain: more characters stripped, more invocations found. Review proved it lost matches. Stripping a soft hyphen joins `run` to the slash, and `run/pay-invoice` then reads as a path. The same shape appeared one layer up. The gate scanned a schedule's name as stored, but the executor reads it through `platform_prompt_service._sanitize_field`. That function collapses `---` to `-` and cuts at 80 characters with `…`, which NFKC turns into `...`. So `run /pay---invoice` and an 80-character name ending in `/pay-invoicexyz` both reach the model as `/pay-invoice`, while the raw value matches nothing.
**Lesson**: Any normalisation between what the gate reads and what the model reads can create a match as easily as remove one. That covers stripping, collapsing, truncation and the renderer's own sanitiser. Match every form the reader can see and take the union: removed AND spaced for invisibles, raw AND rendered for prompt fields. Then assert the union with rows where exactly one form matches. Two global forms are still not enough when the right choice differs by position: `run\u00ad/pay\u200d-invoice` needs the first invisible read as a space and the second removed. So the removed form reads a run right before a slash as a space. A fix that only adds normalisations needs a test that the pre-existing matches survive it. Here, four existing invocations would have silently stopped matching.
