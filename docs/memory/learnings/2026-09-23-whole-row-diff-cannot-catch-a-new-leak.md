## 2026-09-23 — pitfall — A "whole row minus the withheld fields" assertion cannot catch a NEW leaking field
**Context**: #2955, `tests/unit/test_ent549_file_audience.py` §5. The plan (and two independent review voices) claimed that asserting `key_row == {**jwt_row, <withheld fields>: None}` makes "a fourth audience field added tomorrow show up and have to be classified". It does not: an ungated new field is EQUAL in both rows, so the assertion stays green while the field leaks to every key. The whole-row form only catches OVER-withholding or a field that differs.
**Lesson**: A disclosure test that must force classification of future fields has to pin the response's KEY SET (a literal, e.g. `_OWNER_ROW_FIELDS`) as well as compare values — then adding a field turns it red until someone decides which side of the line it is on. Also assert the privileged row's withheld values are non-null, or the comparison is vacuous. Mutation-check it by adding an ungated field to the response model.
