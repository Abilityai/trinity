## 2026-11-27 — pitfall — A value a rating returns when it fails closed is not evidence for a rule that grants on that value
**Context**: #4173. `turn_tier_service` rates a continuation whose turn cannot be read as `share` with nobody behind it: the fail-closed answer, correct for every existing consumer, because each of them only REFUSES on `share` (no shell, no reads, no standing work). #4173 added the first rule that GRANTS on `share` (a share-tier turn reads its own row and the runs it started). A wake of the owner's turn that failed closed at that moment would have passed the tier check and opened the owner turn's runs. The tests were green: every fixture rated `share` because it was a share turn.
**Lesson**: before a new rule grants on a rating, list what else returns that value. When one of them is the rating's failure default, the grant must re-establish the fact itself (here: read the turn the continuation names and rate that row) or refuse. Test it by forcing the failure answer over a row that would otherwise rate higher; a fixture that reaches the value honestly cannot show the difference.
