## 2026-11-04 — pitfall — A router imported inside a unit test can hold a different `get_current_user` than the one the test overrides
**Context**: trinity-enterprise#962, `tests/unit/test_ent962_person_memory_owner_view.py`. `tests/conftest.py`'s #762 autouse fixture restores a baseline `sys.modules["dependencies"]` around every test. A router imported lazily inside one test bound that test's `dependencies` functions. A later test's `from dependencies import get_current_user` then returned the baseline object, so `app.dependency_overrides[get_current_user]` missed and every request answered 401 "Not authenticated". Each test passed alone and failed after the first.
**Lesson**: In a unit test that overrides a FastAPI dependency, import the router and the dependency it is overridden on together at module level (collection time), as `test_85_brain_orb_settings.py` does. Never import them inside a helper called per test. A 401 from `oauth2_scheme` in a test that sets `dependency_overrides` means the override key is a different function object, not that the auth logic changed.
