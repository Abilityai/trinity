## 2026-11-06 — pitfall — A branch/ref policy must be judged on what the build will clone, and the clone mode is decided after the check
**Context**: trinity-enterprise#591 (PR #4311 review). The template-source bound's `github:o/r@ref` pin compared the requested `@ref` / `source_branch`. But a working-branch agent (`source_mode: false`) clones the repo's DEFAULT branch — `startup.sh` passes `-b` only in source mode — and ent#705 can switch a create into working-branch mode on its own (`_apply_agent_kind_default`), after the bound had already admitted it. A copy treats `main` as "the default branch", so `@main` matched a pin while the build snapshotted whatever the default was. Every input the check read was correct; the build simply did not use them.
**Lesson**: (1) Before writing a check on "which ref", trace the build to the line that clones (here `startup.sh` and crud's copy staging) and list every mode that ignores the requested ref. (2) If the mode is decided later than the check, either fix the mode at the check (set it explicitly; ent#705 honours an explicit `source_mode`) or re-check where it becomes final, before the first write. A re-check after a write strands state. (3) A parity test that compares PARSING with the build's parser proves nothing about what the build clones; name it for what it proves.
