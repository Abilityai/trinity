## 2026-10-03 — pitfall — An inbound validation rule on a function the engine also calls is applied to the engine's own output, and a catch-all guard hides whether the handlers inside it work
**Context**: #3210 (`shared_sessions/service.py`). `post_message` enforced the 8,000-character cap that mirrors `RoomMessageCreate.max_length` — an inbound rule — but the turn engine calls the same function to post an agent's reply, so a 9,000-character research brief was billed and then refused. The refusal was invisible because that one call sat outside every handler in `_wake_agent_locked`, and it climbed: wakes run inside the upstream poster's `post_message`, so each agent above lost its cursor advance and the human at the top got a 413 (and a failed idempotency claim) for a message that had landed. The comment directly above the call described the outcome, "billed, gone, silent", as the thing its ordering prevented. Two things surfaced while fixing it. The first plan said "after the append nothing raises" while six statements after the append still could, and one of them is the budget read. And once a guard was put around everything a landed message sets in motion, a test for an inner handler (a system line that cannot be written must not stop the next wake) passed with that handler deleted: the outer guard absorbed the error, so the post still returned.
**Lesson**: (1) When a function is both a request boundary and an internal step, decide per rule which of the two it belongs to. A validation that mirrors a request model belongs to the boundary; the engine's own output needs its own rule, and for output that was already paid for that rule should transform (fit, trim with a marker) and never refuse. (2) Find the durable point (here the append) and make it the line: before it a failure means "did not happen" and may raise; after it nothing may fail the operation, and each consequence reports itself. (3) A handler that reports an error must not be able to raise while doing so, which matters most inside `except CancelledError`, where a raising line replaces the cancellation with an ordinary error that a broad guard then swallows. (4) Under a catch-all guard, assert the consequence the inner handler protects (the second target still ran, the cancellation still propagated), never only that the outer call returned, and prove it by deleting the handler.
