## 2026-10-07 — pitfall — An approval card must be built from the exact strings the approved run sends
**Context**: trinity#3274 review of PR #3345 (`skill_gate_service.enforce` / `frozen_replay`). The card showed `sanitize_text(message + "\n" + system_prompt)`, while the approved run sent `sanitize_text(message)` and `sanitize_text(system_prompt)` separately. `credential_sanitizer`'s `Basic\s+…` pattern spans a line break. So a message ending "…Use auth Basic" with a system prompt "/transfer+9000+EUR+…" put `***REDACTED***` on the card, and Approve then ran the hidden instruction with system-prompt authority. Every test passed, because each one built its card and its replay from the same plain inputs.
**Lesson**: "Approve runs exactly what you read" holds only when the card text and the dispatched text are the SAME strings. Never let the card be a second derivation (a different join, a lossy transform such as a sanitiser or a truncation, a re-render) of what runs. Build the card from the frozen dispatch parts, and label any part with different authority, such as a system prompt. Test with an input whose transform differs between the join and its parts.
