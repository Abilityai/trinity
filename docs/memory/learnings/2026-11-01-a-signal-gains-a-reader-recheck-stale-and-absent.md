## 2026-11-01 — pitfall — A signal built for one reader carries that reader's tolerance; a second reader has to re-check stale and absent
**Context**: trinity-enterprise#1002. The skill-gate marker existed to decide an outage: with no verdict from the platform, present refuses and absent allows. A stale marker was harmless there, because it only mattered during an outage, so `spawn_gate_marker_sync` skipped ungated agents on start to save an exec. Then `bash-guardrail.py` started reading the same file on every Bash call. Clearing the last gate on a stopped agent leaves the marker, which survives stop and start, so an agent with no gates would keep refusing nested CLIs. The healing path was also reachable only from the reader that existed first.
**Lesson**: when a flag, marker or cached fact gains a second reader, re-derive what stale and absent mean for that reader before reusing it. Check three things: who removes it in every state (a stopped agent cannot be exec'd), whether a cost-saving skip was only safe for the first reader, and whether the repair path is one the new reader's traffic ever reaches.
