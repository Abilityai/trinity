## 2026-11-13 — pitfall — A time-bucket dedup key collapses events the holder itself caused
**Context**: #4536. `caller_wake_service` keyed the wake on `caller_wake:{caller}:{15 s bucket}` and told the woken turn "`list_recent_executions` is the complete list". A run the wake turn itself started, ending inside the same bucket, was replayed against the wake's own claim and dropped with an INFO line — a fast delegate→wake loop stalled after three rounds, no audit.
**Lesson**: A dedup window is only sound for events the holder can still observe. Before collapsing a replay, ask whether the event happened after the holder acted (here: after its claim, while it ran or after it finished). Release the key when the holder's work ends, collapse only events from before the claim, and park the rest for the holder's end to deliver — never drop a collision silently.
