## 2026-10-28 — pitfall — A `ref()` around a browser object returns a proxy, so an identity check against the raw object never matches
**Context**: #3445. `utils/websocket.js` held the app-wide socket in `ref(null)`. The fix made each handler ignore events from a socket that is no longer current (`if (ws.value !== socket) return`), so a late close from a socket let go of on sign-out could not null its replacement or schedule a second connection. With `ref`, `ws.value` returns a deep reactive proxy of the `WebSocket`, which never `===` the raw object the handler closed over. Every handler then ignored every event: no message was handled and no reconnect ran. Three existing operator-stream tests went red; the new lifecycle tests alone would have stayed green on half the cases.
**Lesson**: Hold non-plain objects (a `WebSocket`, an `EventSource`, an `AbortController`, a class instance) in `shallowRef` or a plain module variable. Use `ref` only when deep reactivity is the point. Before writing `holder.value === original` or `!==`, check whether `holder` is a deep `ref`/`reactive`; if it is, compare with `toRaw(holder.value)` or change the holder.
