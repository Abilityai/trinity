## 2026-10-10 — pitfall — "never 500s over a malformed blob" must cover a well-formed JSON blob of the wrong TYPES when a response_model projects it
**Context**: trinity-enterprise#692 review (`skill_service._read_last_fleet_reinject` → `GET /api/skills/library/status`, `response_model=SkillsLibraryStatus`). The reader caught `json.loads` failures and non-dict values, but a parseable dict with a `null`/string count passed both checks and failed `FleetReinjectSummary` at RESPONSE validation — a 500 on a route every agent's Skills tab reads, from a settings row any direct DB write or older/newer writer can shape.
**Lesson**: when a stored JSON blob is surfaced through a typed `response_model`, the fail-soft read must validate against THAT model (`Model.model_validate(blob)` inside the same `try`) and degrade to absent — `isinstance(dict)` only proves it parsed. Test it with wrong-typed fields (null, str, list), not just unparseable text.
