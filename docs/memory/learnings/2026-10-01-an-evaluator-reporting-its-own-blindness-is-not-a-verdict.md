## 2026-10-01 — pattern — An evaluator reporting its own blindness is not a verdict, and a "custom prompt" slot that replaces the template is how it goes blind

**Context**: trinity#2959 (VALIDATE-001). Four weekly schedules with validation on: 1 PASS in 12, one high-priority "Validation Failed" alert per *successful* run. The validator's own words were "no run output or transcript was provided to inspect" — and the platform recorded that as `failed_validation` on a parent whose response ended with exactly the status line the validator was asked to find. Three defects shared the symptom. (1) `validation_prompt` is documented everywhere as "your own auditor instructions", but the code used it as the whole template: `custom_prompt or DEFAULT_VALIDATION_PROMPT` then `.format(...)`. Instructions carry no `{execution_response}`, so the run never reached the model — the configuration the docs invite is the one that disconnects the input. (2) The response was cut to its first 10,000 characters, and a run's status line is by convention its *last* line, so a long response lost precisely the line being judged. (3) "The validator received nothing" and "the validator found the work wrong" mapped to the same `business_status` and the same alert, so the signal inverted: wrong four times a week, and the operator disabled the feature. Every test passed throughout — they asserted the template substituted its placeholders, never that a prompt built from an *instructions-shaped* value still carried the run.

**Lesson**: (1) When a model is asked to judge an input, decide "there is nothing to judge" **platform-side, from the input, before the call** — a distinct outcome (`validation_unavailable`), not a FAIL and not a PASS, and never accepted from the model's own answer (a judge able to return "unavailable" can silence its own alert). The tell in a field report is cost/duration splitting into two populations: the one real verdict took 46 s / $0.30, the eleven blind ones 13–31 s / ~$0.17. (2) A free-text slot documented as *instructions* must be **framed**, not substituted for the template; honour a full template only when it names the data placeholder, and never run `str.format` on operator-authored text (literal braces, `{x[k]}` and `{x.attr}` all raise — here after the parent was marked `pending_validation` and outside the try, so one pasted JSON example stranded the row forever). (3) When truncating a document for a model, keep the end the convention puts the answer in — head **and** tail, with an omission marker — and size the window from what the judge is asked to find, not from what fits. (4) Test the judge's input through the judge: a fake auditor that PASSes only when the status line is literally in its prompt catches all three defects; a test that asserts placeholders were substituted catches none.
