## 2026-11-02 — pitfall — a column written only at dispatch is NULL on the default path, and a later consumer reads it as "what ran"
**Context**: `schedule_executions.model_used` was written once, at row creation, from the dispatch override (MODEL-001; the deferral was stated in `core-agent.md` AC-7). A schedule or delegated run with no override — the default — recorded NULL. Nothing noticed for months because no consumer needed the value; the Tier-1 judge (abilityai/trinity-enterprise#936) then read it to tell the run's model family and skipped every such run as `model_unknown`. Found only by a real end-to-end run; seeded demo data had the column filled and hid it.
**Lesson**: a column whose name says "what was used" must be reconciled at the terminal write from what the runtime reports (`metadata.model_name` has existed since #678), with the dispatch value kept when present (`COALESCE(existing, reported)`). When adding a consumer of an audit column, run one real end-to-end instance on the *default* configuration before trusting seeded rows — seed data is written by hand and carries the author's assumptions about which columns are filled.
