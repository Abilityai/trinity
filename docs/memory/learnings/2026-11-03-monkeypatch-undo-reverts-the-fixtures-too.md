## 2026-11-03 — pitfall — `monkeypatch.undo()` inside a test reverts the fixtures' patches too, including the database it runs on
**Context**: trinity-enterprise#341, `tests/unit/test_ent341_tool_access_routes.py`. A race test patched `db.get_tool_access_row` with the function-scoped `monkeypatch`, then called `monkeypatch.undo()` to restore it before asserting on the row. The same `monkeypatch` object is shared with every fixture the test uses, so `undo()` also reverted `db_backend`'s `TRINITY_DB_PATH` and the `world` fixture's container stubs: the next DB read returned `None` and the test failed with `TypeError: 'NoneType' object is not subscriptable`, which reads like a product bug.
**Lesson**: never call `monkeypatch.undo()` to restore one patch mid-test. Restore that one attribute by hand (`try:` / `finally: del obj.attr`, or save and reassign), or use a separate `pytest.MonkeyPatch()` context (`with pytest.MonkeyPatch.context() as mp:`) for the patch you want to undo early. The shared fixture is scoped to the whole test, fixtures included.
