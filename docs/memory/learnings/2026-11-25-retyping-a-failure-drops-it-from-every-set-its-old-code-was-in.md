## 2026-11-25 — pitfall — Giving a failure its own code silently removes it from every set the code it used to carry belongs to
**Context**: trinity-enterprise#978. The turn check that could not ask the platform answered 503, which every path coded `auth`. The fix gave it its own code, `turn_check_unavailable`, so no subscription walk and no AUTH breaker count would act on it. But `auth` was also a member of `operator_resume_service.NO_TURN_ERROR_CODES` ("no turn started, the owed wake stays owed"), and the new code was not, so an answered ask's resume wake would have been marked woken for a turn that never ran. Nothing failed: the set is consulted by membership, and a code it has never heard of reads as "a turn ran".
**Lesson**: When a failure moves from an old code to a new one, list every set, map and `in (...)` test the OLD code appears in (`grep -rn '"auth"\|AUTH.value'`), and decide for each whether the new code belongs there too. The point of the new code is to leave the sets it was wrongly in (here the switch and the breaker), not all of them. A membership set fails open for an unknown member, so its own test should name every code, as `test_ent1108_deferred_wake.py` does.
