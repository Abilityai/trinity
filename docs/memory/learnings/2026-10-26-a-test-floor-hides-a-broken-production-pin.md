## 2026-10-26 — pitfall — A test-environment version floor can make a regression test pass on a broken production pin
**Context**: #3940. The scheduler image pinned `APScheduler==3.11.0`, whose `CronTrigger` loops at every DST fall-back; `tests/requirements-test.txt` said `apscheduler>=3.11.0`, so CI (and the local venv, at 3.11.2) ran a fixed release. A fold regression test written against that environment passes with no fix at all. Same shape as #1823 (`tzdata` declared in tests, absent in the image): the test environment was more capable than production.
**Lesson**: for any dependency whose behaviour a test is ABOUT, the test environment must pin the image's exact version, and the test must assert it (installed version == image pin) before asserting behaviour. Prove the test with a mutation on the real old version, not by reading the changelog. And when a bug is about DST folds, do date arithmetic and comparisons on UTC instants: same-zone datetimes compare by wall clock, and `local + timedelta` resets `fold`, which silently moves a time inside the repeated hour by an hour (it fooled this fix's own first probe).
