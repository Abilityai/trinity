## 2026-10-01 — pitfall — A wrapper's argv is a contract with a binary the source tree does not contain; a build-time parse smoke is what makes flag drift fail the build

**Context**: trinity#2971. `gemini_runtime.py` spawned `gemini --system-prompt … --max-turns N` and the base image installed `@google/gemini-cli` unpinned. The release the image took has a strict parser with neither flag, so every headless Gemini run (the backend always sends a system prompt) exited during argument parsing, and every turn additionally failed the trusted-folder check (exit 55, `--yolo` silently downgraded). Nothing in CI could see it: the unit tests mocked `Popen` and asserted the argv the runtime *built*, never that the binary *accepted* it; no PR workflow builds the base image; and the 2026-09-30 lesson (pin everything) would only have frozen the mismatch in place — a pinned binary still rejects a flag the wrapper invented.

**Lesson**: (1) Every flag a runtime wrapper passes to an external CLI is an assumption about a binary that lives outside the repo, so pinning the version is necessary but not sufficient — the pin must come with a **build-time smoke that performs a real argument parse** of every argv shape the wrapper emits against the installed binary (`gemini … --list-sessions` parses the full argv and exits without an API call; the expected exit per shape is asserted, including the non-zero "parsed but session missing" one). Put it in the image build so flag drift fails the `docker build`, the one place the real binary exists, not the first production turn. (2) Build the argv in **one stdlib-only module** that the Dockerfile can run directly, and have the runtime import from it — then the smoke exercises exactly the argv production code emits rather than a hand-copied list that drifts (the `AUDIT_CLI_VERSION` / `PLATFORM_DENIED_TOOLS` shape from #2468, applied to flags). (3) Prefer a flag over an environment variable for a safety-relevant switch (`--skip-trust` over `GEMINI_CLI_TRUST_WORKSPACE`): a renamed flag fails the smoke, a renamed env var silently reverts to the unsafe default. (4) When a CLI has no equivalent for a guardrail (`max_turns` on gemini-cli), say so in the log and the docs and name what bounds the run instead (wall-clock) — a silently dropped argument reads as enforced. (5) A unit test that pins the wrapper to a transcribed option table (`gemini --help` of the pinned version, dated) catches the wrapper side of the drift on every PR; the image smoke catches the binary side on every build; neither alone covers both.
