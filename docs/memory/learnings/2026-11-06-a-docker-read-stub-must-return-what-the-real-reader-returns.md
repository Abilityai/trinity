## 2026-11-06 — pitfall — A Docker-unreadable stub must return what the real reader returns: `list_all_agents_fast` answers `[]`, it never raises
**Context**: trinity-enterprise#591 (PR #4311 review); second occurrence of the 2026-10-13 "a stub's default return value has to be one the real function can produce" class. The impact view caught exceptions to report "couldn't read", and its test stubbed `list_all_agents_fast` to `raise`. The real function swallows every Docker fault and returns `[]` (the #2196 trap), so production showed "no agent-created agents" while Docker was down. The test was green because it exercised a branch production never reaches.
**Lesson**: When a reader is known to collapse "unreadable" into an empty answer, decide readability with the tri-state reader (`docker_service.agent_container_states()`: `None` = could not ask, `{}` = asked, nothing there) before trusting the empty list, and stub the failure the way the real function fails (`[]` plus a `None` tri-state), never with an exception it cannot raise. Grep the reader's `except` arms before writing the stub.
