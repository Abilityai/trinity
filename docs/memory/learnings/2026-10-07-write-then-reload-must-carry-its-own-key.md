## 2026-10-07 — pitfall — A store write that reloads afterwards must carry its own key, not read "current" after the await
**Context**: #3330 (ent#756) `stores/capabilityGrants.js::setGranted` read `agentName.value` before the PUT and called `load(name)` after it; `load` resets the store when the name differs from current. Switching agents mid-PUT reset the store back to the OLD agent, so the panel for agent B showed A's grants and its next toggle granted on A. The generation guard on `load` did not help: it protects a READ from landing late, not a write's follow-up reload from re-targeting the store.
**Lesson**: In a single-instance store keyed by "the thing on screen", a write action takes the key from its caller (the component prop), and every post-await step (reload, error, busy flag) is conditional on that key still being current. Test it mounted: start the write, `setProps` to another key, resolve, then assert the next write's URL.
