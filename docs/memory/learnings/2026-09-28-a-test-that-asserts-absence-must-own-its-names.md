## 2026-09-28 — pitfall — On a shared per-run database, a test that asserts a row is absent must own its agent and ids

**Context**: trinity-enterprise#611 PR B, `tests/unit/test_ent611_native_ask.py`. The unit conftest pins one SQLite database for the whole run, and pytest-randomly reorders the tests in a file. `test_an_agent_may_not_author_a_gate_id` asserted that `gate-call-abc` did not exist on its agent after the refusal. A sibling test in the same class creates `gate-call-abc` on that same agent, so whenever the sibling ran first the negative assertion failed. It failed on 2 of the 3 nightly seeds and on 8 of 12 other seeds, and passed on 12345, the one seed PR CI uses. So PR CI stayed green, and the dev nightly would have gone red after the merge. The reviewer caught it. The same PR had already hit the class once, in a race test whose `race-1` id was also created by a concurrent-cap test on the same agent.
**Lesson**: A test that asserts a row is ABSENT, or whose outcome depends on which asks have already expired on an agent (the re-ask guard scans them), uses an agent no other test writes to. A name unique to the file is not enough. Prove it before pushing: run the file under the nightly seeds (`NIGHTLY_SEEDS` in `.github/workflows/backend-unit-nightly.yml`) plus a handful of others, because the PR's single seed is exactly the one order that hides the collision.
