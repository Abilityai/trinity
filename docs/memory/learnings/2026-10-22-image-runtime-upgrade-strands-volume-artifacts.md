## 2026-10-22 — pitfall — An image runtime upgrade does not reach what the home volume built against the old runtime
**Context**: #3886 (PR #3890) moved the agent base image from Node 20 to 24. The first cut was verified on a fresh image and looked complete; `/review` found that `~/.npm/_npx` lives on the persistent `agent-{name}-workspace` volume, survives the recreate, and npx reuses a cached tree as-is — so every existing agent's npx MCP server with a native addon would have died with `NODE_MODULE_VERSION 115` vs `137` (reproduced in the real image on a volume a Node 20 container had filled). Same shape as #2114 (a stale `.env` key on the volume outliving every recreate).
**Lesson**: "recreate the agent to pick up the new image" only replaces what is IN the image. Before bumping any runtime in `docker/base-image` (Node/Python major, a CLI's on-disk format), list what the home volume caches or compiled against the old one (`~/.npm/_npx`, `~/.local` pip/venvs, project `node_modules`) and decide per item: re-fetchable cache → clear it at boot on a stamped version change (`startup.sh`, a missing stamp counts as a change); agent-owned files → leave them and log. Verify on a volume populated by the OLD image, never on a fresh one — a fresh-image smoke cannot see this class.
