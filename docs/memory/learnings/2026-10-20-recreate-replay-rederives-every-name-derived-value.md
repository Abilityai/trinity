## 2026-10-20 — pitfall — A recreate that replays the old container must re-derive every value keyed on the agent's name
**Context**: #3813. `recreate_container_with_updated_config` seeds `env_vars` and `labels` from the OLD container's `Config`. Rename (#1159) taught it to re-derive `TRINITY_AGENT_AUTH_TOKEN` from the live name, but `AGENT_NAME` and the `trinity.agent-name` label were still replayed. The agent server reads `AGENT_NAME` once and uses it for `/health`, heartbeat, pull worker ids, the #1083 result callback and git auto-sync, so a renamed agent called the backend under the dead name and got 403 on every one. The token predicate fired once after the rename and then matched, so nothing ever recreated the agent again: the stale state was permanent and silent. Same replay class as ent#109 (git env), #1809 (version label) and #3106 (OTEL flag).
**Lesson**: In the replay path, every value derived from identity or from current DB/settings state is set or cleared explicitly; nothing that can change after create is carried forward. When fixing one replayed value, grep the create sites (`crud._build_env_vars`, `recreate_missing_container`, `system_agent_service`) for every sibling that bakes the same input, and fix them together. A repair predicate for already-affected agents belongs beside the fix. Gate it to cold start, and treat an absent value as a match, so it neither kills running agents nor recreates the fleet.
