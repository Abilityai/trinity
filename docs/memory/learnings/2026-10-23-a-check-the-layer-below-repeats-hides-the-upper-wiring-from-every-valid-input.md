## 2026-10-23 — pitfall — A check the layer below repeats hides the upper wiring from every valid input; test the input the ORDER decides
**Context**: trinity-enterprise#840, `routers/a2a.py`. The outbound kill switch moved from the handler body into a route dependency (`_enabled: None = Depends(_require_outbound_enabled)`) so the handler's first statement could be the self-gate. Deleting the new dependency line left `test_736` green: `a2a_outbound_service.call_agent` checks the same switch again and maps it to the same 404, so every valid-body request answered 404 either way. The only behaviour the dependency adds is ORDER — it runs before FastAPI validates the body, so a malformed body with the switch off is 404, not a 422 that says the route exists.
**Lesson**: When a check is moved or added for ordering reasons, the regression test must use the input whose outcome only the ordering decides (here: switch off plus an invalid body; and switch on plus the same body, still 422). Duplicate checks below make the upper one unobservable on valid input, so "the 404 still happens" proves the service, not the wiring. Mutate the call-site line itself and confirm a named test goes red.
