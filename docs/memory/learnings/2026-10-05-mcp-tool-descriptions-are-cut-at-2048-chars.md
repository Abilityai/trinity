## 2026-10-05 — pitfall — Claude Code cuts every MCP tool description at 2,048 characters; text past the cut never reaches the model

**Context**: abilityai/trinity-enterprise#568. The `chat_with_agent` description had grown to 2,424 characters across #914 / #2661. Claude Code passes each MCP tool's description through `Fo(desc, 'Tool "<name>" description')`, which keeps `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH ?? 2048` characters and appends "… [truncated]" (read out of the 2.1.289 binary). Parameter descriptions are not cut. No Trinity image sets the variable, so every agent — and every operator's Claude Code — read the description cut mid-sentence. The lost tail was the receipt guidance itself: "check `list_recent_executions`", the `timeout_seconds` note and "prefer `parallel=true, async=true` from the start". That is the behaviour the 2026-09-08 duplicate-dispatch cascade lacked, and it had been in the description, unread, the whole time. A census at the fix found 2 of 149 tools still over the cap (`deploy_local_agent` 2,698, `get_objectives` 2,349; #3234).

**Lesson**: (1) Treat 2,048 characters as a hard budget for an MCP tool description: the rule a model must act on goes first, and per-parameter detail goes in parameter descriptions, which are not cut. (2) Pin the length on the description the server *publishes* — `tools/list` over a real transport, as `src/mcp-server/src/delegation-contract.test.ts` does — not on a source string, so a registration wrapper or a new paragraph cannot slip past it. (3) When a model "ignores" guidance that lives in a tool description, measure the description before rewording it: the guidance may never have been delivered.
