## 2026-10-05 — pitfall — Claude Code cuts every MCP tool description at 2,048 characters; text past the cut never reaches the model

**Context**: abilityai/trinity-enterprise#568. Claude Code keeps only `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` characters (default 2,048) of each MCP tool's description and appends "… [truncated]" (read out of the 2.1.289 binary); parameter descriptions are not cut. No Trinity image sets the variable. The `chat_with_agent` description was 1,436 characters during the 2026-09-08 cascade and 2,035 after #2661 — 13 short of the cap — and #2958 (2026-09-24) took it to 2,424. From then on every agent, and every operator's Claude Code, read it cut mid-sentence, and the lost tail was the receipt guidance itself: "check `list_recent_executions`", the `timeout_seconds` note and "prefer `parallel=true, async=true` from the start". Nothing failed: the server published the full text, and a change to an unrelated paragraph near the top is what pushed the advice past the cut. A census at the fix found 2 of 149 tools still over the cap (`deploy_local_agent` 2,698, `get_objectives` 2,349; #3234).

**Lesson**: (1) Treat 2,048 characters as a hard budget for an MCP tool description: the rule a model must act on goes first, and per-parameter detail goes in parameter descriptions, which are not cut. (2) Pin the length on the description the server *publishes* — `tools/list` over a real transport, as `src/mcp-server/src/delegation-contract.test.ts` does — not on a source string, so a registration wrapper or a new paragraph anywhere in the description cannot slip past it — the edit that cuts the tail is usually not the edit that wrote it. (3) When a model "ignores" guidance that lives in a tool description, measure the published description before rewording it: the guidance may no longer be delivered.
