## 2026-11-03 — pitfall — One agent-supplied field that fails a strict model can empty a whole best-effort list
**Context**: trinity-enterprise#584, `services/connector_service.py::resolve_exposed_playbooks` inside `client_portal/service.py::_agent_briefing`. The agent's `/api/skills` JSON went straight into `ConnectorPlaybook(description=pb.get("description"))`, typed `Optional[str]`. An older agent image passes a frontmatter list through as a JSON list, and pydantic raised on that one entry. `_agent_briefing`'s outer best-effort `except Exception` then returned an empty, `ready` briefing, so every playbook of that agent disappeared from the Workspace (the test measured `total == 0` for three skills, one with a list description). That `except` logs nothing, and the payload looked like "this agent exposes nothing". It is the same class as the 2026-08 YAML-natives entry (#2110), one hop later: agent JSON instead of author YAML.
**Lesson**: Coerce an agent-supplied field to the model's type **per item, before** the strict model is built (here `services/skill_description.py::clean_description`: str passes, scalar → string, collection → None), so one malformed entry degrades to one missing field instead of an empty set. When a best-effort `except` wraps a loop that builds models from foreign data, ask what one bad item does to the rest; a test that feeds one non-text value beside good ones and asserts the good ones survive is the guard.
