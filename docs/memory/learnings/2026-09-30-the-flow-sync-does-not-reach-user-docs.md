## 2026-09-30 — pitfall — The feature-flow sync does not reach `docs/user-docs/`, so a behaviour change leaves the public guide describing the old rule
**Context**: trinity-enterprise#676, PR #3132. The role card's metric staleness changed from "no value, no update time, or older than 30 days" to the platform's 2× cadence rule. Requirements, both feature flows and three architecture files were updated, and `/sync-feature-flows` ran. `docs/user-docs/sharing-and-access/workspace.md` still stated the 30-day rule. The PR review caught it, not the sprint. It is the same class as #2322's lesson (a contract change must sweep `user-docs/` on equal footing), recurring because the doc step every sprint runs covers `docs/memory/` only, and `docs/user-docs/` is auto-published to a public search index.
**Lesson**: When a change alters what a user sees or a rule a user relies on, grep `docs/user-docs/` for the old claim in the same commit as the code: the old number, the old field name, the section heading of the surface. `/sync-feature-flows` and `/update-docs` will not find it. For a Workspace surface, `docs/user-docs/sharing-and-access/workspace.md` is the file; its "Info tab" table also states the order of the sections.
