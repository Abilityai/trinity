## 2026-09-23 — pattern — A verdict that depends on a clock, a global setting and a per-row switch must be an AND at READ time, not a materialised row
**Context**: trinity-enterprise#641. The first design stored `graduated`/`on_request` per (seat, ask class) and re-evaluated on every event. Three of its inputs have no event to hook: records lapse at UTC midnight (nothing fires), the instance autonomy LEVEL is one settings row whose change would have to fan out to every seat of every agent (there is no fleet-wide seat query, and the write path is an admin PUT that must stay O(1)), and an agent's `autonomy_enabled` flips in a different subsystem entirely. Materialised, each of those is a verdict that outlives its own evidence with nobody watching — the exact failure two independent reviewers found first.
**Lesson**: Split the verdict into the half that is *earned* (expensive, event-driven, worth a CAS'd row) and the half that is *ambient* (a clock, a global, a neighbouring flag) and AND them where the answer is read. The ambient half then needs zero writes to take effect, and — the property that actually sells it — restoring the ambient condition restores exactly what was earned, with no recompute and no lost state. The test that proves it is "change the ambient input, assert the verdict flipped AND the row is byte-identical".
