## 2026-10-06 — pitfall — `posixpath.normpath` keeps exactly two leading slashes, so a lexical path gate reads a different file than the one the agent resolves
**Context**: trinity-enterprise#792. The backend file routes normalise a user path with `posixpath.normpath` and compare it against `/home/developer/...` patterns (the #590 deny list, the ent#596 `skills.manage` fence, #3236's `instructions.manage` fence). POSIX leaves a leading `//` implementation-defined, so `normpath('//home/developer/.ssh/x')` stays `//home/developer/.ssh/x` (three or more slashes collapse to one). The string matched no path pattern and no fence, the raw path was forwarded, and the agent server's `Path.resolve()` collapsed `//` to `/` and wrote the real file. The deny-list unit tests ran against an inline copy of the shipped functions, so they could not have seen it. `canvas_blocks.py` had already refused `//` explicitly, so the codebase knew the quirk in one place and not in the other. Review of the fix found a second door of the same shape on DELETE, which carried no deny list: `/proc/self/root/home/developer/…` and `/proc/self/cwd/…` resolve into the home dir inside the agent container.
**Lesson**: (1) A lexical path gate must collapse leading slashes (`"/" + raw.lstrip("/")`) or refuse a `//` prefix. It should also **forward the normalised string it checked**, never the raw input, so the gate and the executor read one string by construction (the #3102 and 2026-10-02 class, one layer down). (2) Bound the class with a property, not a row per report: an independent segment-stack oracle for the normalised form, plus "extra leading slashes never change a verdict". (3) The remaining divergence is symlinks, which a lexical check cannot see. That includes kernel symlinks under `/proc`, so a deny list on any route that acts on a path needs `/proc/*`. Anything beyond that belongs in the agent server, which is the only side that sees the filesystem. (4) Security tests import the shipped function. A "MUST mirror exactly" copy proves nothing about the code that runs.
