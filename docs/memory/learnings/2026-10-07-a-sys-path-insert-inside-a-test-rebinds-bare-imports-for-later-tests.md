## 2026-10-07 — pitfall — A `sys.path.insert(0, …)` made while a test RUNS rebinds every later bare-name import, including `from conftest import …`

**Context**: trinity-enterprise#753. A new route test imported `_route_census` by doing `sys.path.insert(0, tests/unit)` inside the test function. `test_ent500_cascade_rename`'s fixture runs `from conftest import ensure_schema_tables`, which the suite resolves to the ROOT `tests/conftest.py` (on the path through `pyproject.toml`'s `pythonpath`). Run after the new test, it resolved to `tests/unit/conftest.py` instead and errored with `ImportError: cannot import name 'ensure_schema_tables'`, but only in that order. Each file passed alone. `test_2996_human_only_routes.py` makes the same insert at module level, during collection, and breaks nothing. So did the new test once its insert moved to module level.
**Lesson**: In `tests/unit`, put any `sys.path` change at module level, never inside a test or fixture body. Never put the `tests/` root at position 0 either: it is already on the path, and moving it ahead of `tests/unit` changes what a bare `conftest` resolves to. When a sibling test reports an `ImportError` naming `conftest` or a helper module, look for a run-time path mutation in the tests that ran before it before you suspect your own code.
