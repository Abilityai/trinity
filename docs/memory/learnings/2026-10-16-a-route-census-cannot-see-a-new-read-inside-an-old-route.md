## 2026-10-16 — pattern — A route census sees a new ROUTE, never a new READ inside an existing one; guard the read helpers, and make the viewer tier an allowlist
**Context**: trinity-enterprise#875. Execution reads (list, detail, log, stream, queue, fleet list, activity timeline) and control verbs (terminate, model, force-pull, webhooks) sat at the accessor tier, so a person an agent was merely shared with read every other person's prompts and steered the agent. The issue listed ten routes; a census of every router found about twice that, including two the issue never named (the activity timeline, which carries the first 100 characters of each prompt, and the container's raw log). Independent review then found the fix's own first draft wrong in two directions: the webhook-rotation list filtered on "creator is not the owner", which excludes exactly the attack (a share holder minting on a schedule the owner created), and the "key" tier was a denylist over a free-text scope column.
**Lesson**: (1) A table-driven route census (route -> tier) is necessary and blind to the likeliest regression: a route that already exists gaining a call to an unfiltered read helper. Add an AST guard over the router call sites of the read helpers (`get_execution`, `get_*_executions*`, `get_activities_in_range`): every site either decides on the viewer or is listed with a reason, and a listed site that no longer reads fails as stale. (2) Name the viewer tiers once and make them an allowlist in both directions — person, key, and everything else filtered — because the scope column is free text and a principal with no `mcp_scope` must not read as the JWT value. A bare `MagicMock` principal in an older test correctly lands in the filtered tier; fix the test's principal, not the tier. (3) Narrow in the WHERE, before LIMIT/OFFSET and before any `LIKE`, and prove it on a real SQLite with the caller's rows the OLDEST and another person's rows the newest; a Python-side post-filter passes every stub and fails this one. NULL `source_user_id` never matches `=` — keep it that way (hidden, fail closed). (4) When a credential's minter is not recorded, a remediation list cannot be filtered by who "probably" minted it: list the whole population the exposure covered (every webhook on an agent that is shared today, `--all` for ever-shared) and make the tool fail loudly on an unreadable database instead of printing nothing. (5) State the residuals you chose not to fix where the next reader looks (here: the documented loop reach, the Workspace team view, `/ws` previews), so "not fixed" reads as a decision, not an oversight.
