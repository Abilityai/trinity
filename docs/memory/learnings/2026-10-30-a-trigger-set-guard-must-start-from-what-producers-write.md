## 2026-10-30 — pitfall — A trigger allow-list guard must enumerate what producers write, not what the set already holds
**Context**: #4105. `self_task` (an agent's `POST /task` to itself) and `skill_gate` (a requester's wake after a gated request is decided) were in neither `pull_pilot.PULL_REACHABLE_TRIGGERS` nor `PULL_REACHABLE_NON_AUTONOMOUS`, so on a pull pilot they were pushed onto free Redis slots while the pulled parent turn held a worker: four turns ran against `max_parallel_tasks=3`, invisible to the soak's M3 probe (counts `claimed_by_worker`) and canary S-02 (counts the slot ZSET). The runtime diagnostic `note_unreachable_pull_trigger` could not catch it twice over: it only considered triggers already in `_AUTONOMOUS_TRIGGERS` (so a trigger in no set was out of its scope), and it ran only in `execute_task`'s un-held-slot branch, which the `POST /task` route never reaches because the router pre-acquires its slot. #2845's class guard scanned scheduler literals only.
**Lesson**: (1) A guard that checks "every member of set A is classified in set B" cannot see a value that is in neither set. Start from the producers: `tests/unit/test_4105_pull_trigger_census.py` reads every `triggered_by` written in `src/backend` + `src/scheduler` (both arms of a conditional, `*_TRIGGER` constants resolved, `track_activity` skipped, non-empty floor) and requires each in a pull set or `PULL_UNPULLED_TRIGGERS` with a reason. (2) A runtime diagnostic for a dispatch decision belongs where every producer converges (`capacity_manager.acquire`), not in one producer's branch; check every route that reaches the decision with a held slot or a pre-built payload before trusting "this never fires".
