## 2026-11-18 — pitfall — When a classification starts deciding a priority, every fallback that yields the calm value becomes a way to hide an emergency
**Context**: #4636 / #4635, `services/queue_stall_service.py`. The stall monitor's wait reasons were labels until busy waits (`capacity`, `agent_busy`, `conversation_busy`) began filing at medium instead of high. Three readings that had been harmless then filed a dead or refusing pool as "expected": an unreadable cap fell back to 1, so one held slot read as a full pool; the leased-row count included expired leases, so a dead pool read as full until the reaper ran; and only the FIFO head was classified, while the pull claim skips a head whose conversation is running — a claimable row stuck behind a refusing pool filed at medium, and a person's ending snoozed it. Canary B-02 already measured both states the right way (unexpired leases only, the oldest claimable row). Nobody had held the monitor to that, because nothing depended on the label.
**Lesson**: when a label gains a consequence (a priority, a page, a snooze), re-audit every path that can produce its calmer value — fallbacks, proxies, defaults, "first row" shortcuts — and make each one fail toward attention: unknown is never "fine". Where another component already measures the same state for an alarm, adopt its definition rather than the cheaper proxy. The mirror image of 2026-08-25 ("demoting a severity removes everything gated on it").
