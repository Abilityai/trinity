## 2026-11-02 — pitfall — A bound on one branch of a reach predicate is skipped by the other branch
**Context**: trinity-enterprise#871, `/cso --diff`. `files._may_reach_for_path` applied the capability owner bound only after `agent_may_reach` said no. An edge made it say yes first, so an agent holding `instructions.manage` with an edge to another user's agent wrote that agent's `CLAUDE.md`, past a bound the docs stated for every holder. The route's capability gate passed, because the grant was real.
**Lesson**: put a bound at the point that enforces the grant, not in the predicate that decides reach. A predicate has several ways to answer yes, and only the enforcement point runs on all of them. When a test proves a bound, also drive it with reach that arrives another way: an edge, a spawn, the agent itself.
