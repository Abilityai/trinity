## 2026-11-02 — pitfall — An overflow box that is not positioned does not contain `sr-only` children, and Chrome counts them in the page's height
**Context**: trinity#3448, `components/BoundedRegion.vue`. The Library's 112 cards scrolled correctly inside a filled region, and the page was still 7,058 to 26,207 px tall with nothing visible below the box. Each card's `AssignedAgents` renders a `<label class="sr-only">`. `sr-only` is `position: absolute`, and `overflow` only clips a descendant whose containing block is the box or inside it, so with no `relative` on the box the labels resolved against the page and extended its scrollable area. The flex chain was right and every jsdom spec was green. Firefox reported the correct height, so a Firefox pass proved nothing either: it was found by eye.
**Lesson**:
1. A scroller that holds arbitrary content must be `relative` (or otherwise a containing block), and that belongs on the shared primitive, not on each consumer. Making it one also means an absolutely positioned popover inside now clips, so audit consumers and teleport those.
2. A list count that should not move the page is proved by the page's height against the window, in Chromium, with a fixture that renders what the real cards render. Here the label appears only with `assignable_agents` non-empty, so a thinner fixture passes with the bug.
3. Compare one window at two item counts: the assertion is relative, and it holds at a window too short for the region's floor.
