## 2026-10-06 — pitfall — A base-vs-branch unit-suite failure diff is noise unless both runs disable pytest-randomly

**Context**: trinity-enterprise#665. Two full `tests/unit` runs on the branch and one on `origin/dev` disagreed on 26, then 10, failing tests: `test_2915_*`, `test_ent477_*`, `test_retention_floor`, `test_1081_*`, `test_2638_*`. Each passed in isolation. Bisecting the "polluter" found nothing, because `pytest-randomly` reshuffles the order on every run, and adding one test file changes the shuffle even under the same seed. With `-p no:randomly` on both sides, the two failure sets were identical.
**Lesson**: To ask "did my diff break anything?", run base and branch with `-p no:randomly` and compare the sorted `FAILED` / `ERROR` lines. Only a failure that appears on the branch under the same fixed order is a regression; run it alone next. An order-dependent failure found under a random order belongs to whichever pair of tests the shuffle happened to place together, so do not bisect it against your own file.
