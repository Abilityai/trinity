## 2026-10-30 — pitfall — A key the receiving Pydantic model does not declare is dropped silently, and a dict-level test pins it green
**Context**: trinity#3618. The pull worker's cancel relabel (`docker/base-image/agent_server/services/pull_worker.py`) wrote `"error": "Execution terminated by user"` into the §3.3 result body. `PullTaskResultRequest` (`src/backend/models.py`) has no `error` field and ignores extras, so the sink stored the stream parser's fallback from `content` as the row's error and response. The unit test asserted `body["error"]` on the worker's dict, so it passed on the exact key the backend throws away.
**Lesson**: When code on one side of a wire builds a body as a dict, assert it through the receiving side's model (`Model(**body)`), never on the dict alone, and assert the dead key is absent. A dict assertion proves the producer wrote a key, not that any consumer reads it. This is the same class as a mirror test pinning drift as the requirement: the test encodes the producer's belief about the contract.
