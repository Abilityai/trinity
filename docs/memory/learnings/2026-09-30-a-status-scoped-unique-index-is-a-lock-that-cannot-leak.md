## 2026-09-30 — pattern — A status-scoped partial unique index is a mutex every state transition releases
**Context**: #2843, `db/schedules/queue.py::claim_next_queued`. One turn per conversation on the pull queue needed mutual exclusion across N workers, released on every exit: terminal write, lease-expiry requeue, park, reaper. A Redis or row lock needs an explicit release on each of those paths, and a missed one silently locks a conversation out.
**Lesson**: When "at most one X in state S" is the rule, put it in the database as `UNIQUE (scope, key) WHERE status = S AND key IS NOT NULL`. Every transition out of S releases it by construction, so there is nothing to leak. Pair it with a claim-side `NOT EXISTS` over the same predicate so the common case skips the row instead of erroring, and treat the `IntegrityError` as the race backstop that the claim retries. The `NOT EXISTS` reads committed state and cannot stop two concurrent claimers on its own; only the index can, so the regression test must be a concurrent Postgres harness and must go red with the index dropped. Declare the index in `db/tables.py` too, or autogenerate proposes dropping the rule.
