## 2026-09-30 — pattern — A chain counter derived from "what is running now" loses the chain at every async or deferred hop
**Context**: trinity#2973 (follow-up to #2806). Chain depth was `1 + MAX(chain_depth)` over the caller's RUNNING rows. Loops (iteration N runs after the starter's turn ended), task-completion events (fired after the row went terminal) and event loopbacks (async `/task`) all read 0 there, so each re-rooted the chain.
**Lesson**: When a limit is inherited across a hop that can outlive the caller's live state, stamp the value on the artifact that crosses the hop — the loop row, the scheduler request body, a signed loopback JWT claim, the finished row's own column — and read it from there. Deriving it from live state at the receiving end is correct only for synchronous hops. When the artifact cannot be read (row fetch failed), fall back to the limit, never to 0.
