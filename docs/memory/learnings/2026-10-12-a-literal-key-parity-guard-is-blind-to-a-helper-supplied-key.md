## 2026-10-12 — pitfall — a literal-key parity guard is blind to a helper-supplied key; pin the writer set by call, not by key
**Context**: #3590. Three sites assemble an agent container's env — `crud._build_env_vars`, the config-drift recreate and the #1559 rebuild-from-nothing. The pull-worker opt-in (`TRINITY_PULL_MODE`, `TRINITY_MAX_PARALLEL_TASKS`) reached the first two through `pull_mode_env_vars()` and the third never applied it, so `docker rm -f` + `POST /start` rebuilt a pilot with no worker while `is_pull_pilot_agent` (allowlist only) kept routing its work to the durable queue: every task `queued`, no log line, agent healthy. The #1811 create-vs-recovery parity guard was green the whole time, for two reasons that compound: it scans string-literal keys (`env_vars["X"] = …`, `{"X": …}`), and a key that arrives via a helper call is not a literal on either side; and it scans `_build_base_env`, one of six create sub-builders — the pull call sits in `_build_env_vars`. The ledger already held "rebuild from nothing re-derives env independently" (ent#123) and "the create path is never one call site" (#1871/#2541); this is the third occurrence on the same function, and the existing guard could not see any of them.
**Lesson**: a property that reaches the container through a *helper* is invisible to a *literal-key* scan, so the guard for "every assembler applies X" is an AST pin on the **call** — each named assembler contains a call to the one owner of X, and nobody else calls past it — not a diff of key names. Lift the idiom into that one owner first (set-or-clear, in place, module-global lookup so existing stubs keep intercepting), then pin the writer set the way ent#109 pins the git-env gate. Pair any allowlist-driven *routing* decision with a *drift predicate* on the executor's actual state (`check_pull_mode_env_matches` in the start chain): routing by config while the executor's capability is a container property is exactly the gap that stays silent, and a predicate heals every assembler omission plus the operator-edited-the-allowlist case in one place.
