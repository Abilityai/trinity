## 2026-10-19 — pitfall — Forwarding an agent's status code: never forward its 401
**Context**: #3677 (PR #3804), `routers/chat.py::_raise_model_route_error`. Passing an agent server's 4xx straight back to the caller was the right fix for a swallowed 400, but the agent's auth middleware also answers 401 when the BACKEND's per-agent token is refused (#1159: rotated `AGENT_AUTH_SECRET`, pre-#1159 container). The browser's `utils/platformSession.js::sessionLostVerdict` reads any 401 on an ordinary page as "session lost" and signs the person out, so a platform-side credential fault would have logged users out on every load of that agent's page.
**Lesson**: When a backend route relays an agent server's status, relay the caller-facing 4xx (400/404/409/422) but treat an agent 401 as the platform's own failure (503 + ERROR). A 401 means "the request's credential failed" to every client, and the backend→agent credential is never the caller's.
