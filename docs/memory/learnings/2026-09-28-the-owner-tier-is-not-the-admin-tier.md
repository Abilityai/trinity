## 2026-09-28 — architecture — The owner tier is not the admin tier: a human-only rule there is per route, and the inheritance mechanism is a classified route ledger

**Context**: #2996 / trinity-enterprise#711. #1890 moved the agent-principal refusal INTO `require_admin` / `assert_admin`, because no legitimate agent flow needs an admin gate. The owner-tier gates (`can_user_share_agent`, `assert_agent_owner`, `OwnedAgentByName`) cannot take the same move: agents legitimately drive owner-gated routes (the MCP schedule tools, file writes), so refusing agent keys inside the gate is a fleet-wide behaviour change.
**Lesson**: When the shared gate carries legitimate machine traffic, put the human-only rule on the route (`Depends(require_person)` for grants, `Depends(require_interactive)` for credential and sign-in-identity writes), and make inheritance come from a guard, not from memory: `tests/unit/test_2996_human_only_routes.py` requires every route, every method, to resolve to one policy class or sit in a shrink-only baseline. A gate only counts in the Depends form or as the handler's first statement on its principal — a check that lives in `services/` is invisible to a router-level scan, which is how the autonomy toggle's check hid.
