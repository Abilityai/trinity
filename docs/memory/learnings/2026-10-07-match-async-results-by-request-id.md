## 2026-10-07 — pitfall — Match an async result to its request by the request's id, never by "newest since my baseline"
**Context**: trinity#3166. The Workspace waited for its reply by polling thread history for the newest assistant row that differed from a baseline read before dispatch. A second turn on the same thread (the chat open in two tabs) landed its reply first, and the first poll returned it as this turn's answer. #2694 had already moved the comparison from a count to a row id; that fixed window shifts but still could not tell whose row it was.
**Lesson**: When a poller waits for the result of a request it dispatched, stamp the request's id on the result row and match on it. "Newest since baseline" is correct only while one writer exists. Treat a row with no id as never this request's (other writers, such as completion reports, write unstamped rows); keep the old rule only when the field is absent (older backend).
