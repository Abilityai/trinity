## 2026-10-10 — pitfall — A marker added to one ending writer must reach every writer's audit row and every ending surface
**Context**: PR #3515 (abilityai/trinity-enterprise#844). The `outcome_unknown` marker was written by both timeout writers in `db/operator_queue.py` (the `mark_expired` sweep and #3247's in-transaction expiry in `_replace_predecessor`), but only the sweep's `expired` audit row in `ask_service.expire` carried it. The replace path in `raise_ask` built its own copy of that audit row inline and missed it. The queue detail panel (`QueueItemDetail.vue`) rendered `queueEndingText` only for platform endings, so an expiry fell through to the "person answered" branch and the marker never showed there, although the PR said it did.
**Lesson**: When an ending gains a new attribute, list each writer that ends a row that way (`grep "disposed_by=\"timeout\""`) and each place that renders an ending (`grep queueEnding`), then check them one at a time. Build a side effect such as an audit row in one function that every writer calls, never as an inline copy at each call site. Test the second writer through the service path that agents and operators actually hit, not only through the db writer.
