## 2026-10-26 — pitfall — A configurable number in an agent error detail is an input to the auth classifier
**Context**: trinity#2328 (slice S2), `headless_executor._finalize_headless_result`. The first draft of the per-task turn-limit 422 said "below the agent's guardrail of {G}". The backend substring-matches every task error detail against `failure_classifier.AUTH_INDICATORS`, which holds bare `"401"` and `"403"`, and `max_turns_task` is owner-set in 1–500 — so an owner who picked 401 or 403 would have turned every per-task turn-limit failure into a SUB-003 subscription rotation plus a retry of a turn that legitimately hit its cap. Every test with the usual guardrail (50, 200) stayed green.
**Lesson**: Before putting any value into an agent-side `HTTPException.detail` (or any text that reaches `is_auth_failure`), ask whether its domain can contain 401 or 403: owner-configured numbers, counts, ports and ids all can. Leave the value out of your own wording (name the setting instead) — the slice's final per-task wording carries neither cap. But that is necessary, not sufficient: the same detail embeds the CLI's own error text, which carries the turn count, so a turn-limit 422 at a cap of 401 or 403 (per-task or guardrail) still reads as an auth failure on push, and did on the guardrail path before #2328. Wording hygiene cannot close a class whose input you do not author; the fix is at the classifier — a turn-limit 422 is never a credential failure (backend follow-up), and word-boundary anchoring of the indicators would retire the substring class for good. Pin both halves by name: `test_2328_turn_cap_tighten_only.py::test_the_per_task_422_wording_adds_no_number_the_auth_classifier_reads` (our text, number-free CLI message) and `::test_a_turn_limit_422_at_401_or_403_is_not_auth_on_push` (the real shape; first pinned as the known exposure, then inverted when #3984 landed the classifier fix, `failure_classifier.is_turn_limit`). A test that fixes the caller's value at 20 and parametrizes only the guardrail cannot see the per-task 401/403 case. Same class as the hex-UUID trip in the #1849 entry.
