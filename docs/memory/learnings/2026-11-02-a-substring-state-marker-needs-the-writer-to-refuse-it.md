## 2026-11-02 — pitfall — a JSON substring used as a state predicate must be unwritable in any other state
**Context**: `db/evaluations.py` — `finish_tier1_row` and `reclaim_stale_tier1` keyed their compare-and-set on `judge_json LIKE '%"state": "claimed"%'`. Review of #3790 (abilityai/trinity-enterprise#936) showed a *finished* document could carry that string in a nested object (the guard checked only `dimensions`), so a reclaim deleted a real verdict and the run was judged — and paid for — twice.
**Lesson**: when a writer matches a serialized-JSON substring to decide a row's state, the validator that admits documents into that column must refuse the marker anywhere in the document (`_CLAIMED_MARKER in json.dumps(doc)` → reject), and must allowlist the top-level keys so an unchecked key cannot smuggle it in. A state predicate over text is only as strong as the guard on what text can be written.
