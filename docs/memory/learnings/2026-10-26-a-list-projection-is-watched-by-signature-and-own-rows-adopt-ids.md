## 2026-10-26 — pattern — A component that reacts to a re-stamped list projection watches a string signature, and adopts server ids onto its own id-less rows before any dedupe
**Context**: trinity#3439. The open Workspace thread never re-read itself; the fix had it react to its own row in the `threads` list the shell already passes down on the 20 s tick. Two reviewers, independently, caught the same two traps before a line was written. (1) The shell's `decorate()` returns NEW objects every tick (unread, stars, drafts re-stamped), so a watcher over the row — or over `() => [a, b]`, which Vue compares by identity — fires every tick and turns "no new timer" into a fetch storm per open chat. (2) The person's own `send()` pushes a user row with no `id` (`local: true`); the first read after their own turn returns the server's copy WITH an id, and an id-only dedupe appends it — the question renders twice on every send. A third, from the strategy side: `unread` looked like the obvious trigger and is wrong twice — it counts assistant rows only (a system notice never moves it) and the turn-end mark-read resets it for a report that landed mid-turn — while `last_message_at`/`message_count` move for every writer through one function (`touch_portal_session`).
**Lesson**: When a component reacts to a row inside a list the parent rebuilds on a cadence, (a) watch a **string signature** of the fields that mean "changed" (`` `${count}|${time}` ``), never the object or a tuple getter; (b) before deduping fetched rows against what is on screen, **adopt server ids onto the surface's own id-less local rows** by content — the local optimistic row is the one thing the server's read will always "discover"; (c) pick the trigger field by asking *which writers move it* — a derived count (`unread`) encodes a policy (who counts, when it resets) that is not "a row arrived", while the row's own `touch` is; (d) when a bounded read comes back entirely unseen, re-read the window and MERGE — the mount path (`loadThread`) empties and pins the viewport, which is an intent, and a background arrival is not (#2624); (e) put `sending`/in-flight flags in the watch *sources* and record the reconciled signature only when a read ran, or a change that landed mid-turn is skipped once and never re-fires. Give the parent a **distinct event** for "I caught up" rather than reusing the turn-done event, whose handler carries side effects (title-settle, list refresh) an agent-initiated row must not drive.
