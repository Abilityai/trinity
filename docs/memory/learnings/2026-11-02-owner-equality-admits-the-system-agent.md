## 2026-11-02 — pitfall — A bound written as owner equality admits the system agent, because the admin owns it
**Context**: trinity-enterprise#871, `/cso --diff`. `owner_owns_agent` was the one bound on a capability holder, and it asked only whether the key's owner owns the target. On an admin-owned install that is true of `trinity-system`, so an agent granted `schedules.manage` could schedule work there and one granted `instructions.manage` could rewrite its `CLAUDE.md`. That text then runs under the `system` key, which bypasses every permission check, so one narrow grant added up to all of them. Grants refused the system agent as a holder (`system_agent_not_grantable`) and nothing refused it as a target.
**Lesson**: when a principal is refused as a subject, ask whether it is refused as an object too. A bound that compares owners says nothing about what the target can do with what lands on it, so an agent holding more authority than its owner's other agents is excluded by name in the bound itself, not on each route.
