## 2026-10-09 — pitfall — An exception to a role floor must name the credential class, not only the principal kind

**Context**: trinity-enterprise#837 (`enforce_operator_floor`, `/review`). The floor refused the Workspace-only `user` rung everywhere except on routes marked `@workspace_route` — for "a person", written as "not an agent". That admitted every KEY on the rung too: a `user`-scoped MCP key minted before the upgrade (no longer listable or revocable by its owner) still minted `/ws` tickets and reached the marked loop routes. The marks existed for the SPA's JWT only. Separately, two doors that resolve a principal outside `get_current_user` (the agent terminal WebSocket, `/ws/events`) needed the floor applied by hand; the plan listed one of them.
**Lesson**: When a floor admits an exception, state who may use it as an allowlist over the CREDENTIAL (`is_interactive_principal`, `is_person_principal`), never as the negation of one principal type — "not an agent" silently includes every key scope, today's and tomorrow's. And before calling a floor complete, list every door that turns a credential into a platform principal without the floored dependency (`decode_token`, direct `validate_mcp_api_key`, WebSocket handlers) and give each a disposition the test suite pins (`test_837_workspace_only_floor.py::test_every_websocket_route_has_a_workspace_only_disposition`).
