## 2026-09-30 — pitfall — A fixture for invisible characters must spell them as escapes, or the file carries the very thing it tests for
**Context**: trinity-enterprise#672, `tests/unit/test_ent672_skill_deprecation.py`. The sanitiser test feeds a right-to-left override and a zero-width space through `skill_packaging._one_line`. The fixture was authored as `\u202e` / `\u200b` and landed on disk as the two raw characters, because the text passed through a layer that decodes escapes before writing. The test was green either way. An independent review found it by scanning codepoints: a raw bidi override in source is the Trojan-Source shape (a hidden-Unicode banner on the PR), and an editor or formatter that strips it leaves the test green while it no longer proves the character is dropped.
**Lesson**: Write control and format characters in test data as escape sequences, and check what is on disk rather than what was typed: scan the changed files for Unicode categories `Cf`/`Cc` before committing (`unicodedata.category(ch) in ("Cf", "Cc")`, tab excepted). `tests/unit/test_compatibility_checks.py` already spells its zero-width space as an escape; follow it.
