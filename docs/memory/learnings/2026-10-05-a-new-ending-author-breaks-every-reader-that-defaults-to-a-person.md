## 2026-10-05 — pitfall — A new ending author is read as a person by every reader whose last arm is "someone with an email"
**Context**: trinity#3247, `client_portal/asks/service.py::_ending_of`. Agents may now end their own pending ask by replacing it (`disposed_by='agent'`, `disposed_by_email=NULL`). The Workspace projection's last arm was "the email matches the viewer → `you`, else → `operator`", so with no new arm a replaced ask would have reached the client as "Cancelled by the operator", which is false and blames a person. The Operations and `/m` util (`endingKind`) and the agent's Ended asks line had the same shape. #3246 adds a fourth author (`platform`) on the same enum at the same time.
**Lesson**: When an enum column gains an author, grep every reader of that column for a catch-all arm that assumes the remaining value is a person (an `else` that falls through to an email, or `who = 'operator'`). Give the new author its own arm and put it BEFORE the email arm, and pin that order with a row that has both the new author and a stray email. Then grep the docs for the enum written out (`person | timeout`, "an enum of two", "only a person ends"), because the prose states the old closed set as a fact.
