## 2026-09-29 — pitfall — A dynamic section in the empty chat moves everything when it lands, twice over
**Context**: the Workspace empty chat (`PortalBriefing`): ent#465's suggestions were slotted ABOVE the static "Things you can ask" hints (`before-hints`, per the 2026-09-24 entry), and the pane's `useStickToBottom` re-pinned on every resize. A suggestions fetch landing after the briefing moved the hints 396→615→425px and scrolled the agent's name from 294 to 104px; a dismissal moved it again. Every unit test passed — jsdom has no layout; it was measured only by sampling `getBoundingClientRect` per frame with the suggestions request delayed.
**Lesson**: in any empty/landing state, order sections static-first — a section with its own fetch, 0–N rows, or dismissal goes BELOW everything that arrives with the page, so its arrival grows into empty space. And a stick-to-bottom scroller must not pin a surface that is not a transcript: `useStickToBottom(el, { enabled })` gates it (the empty chat passes `messages.length > 0 || sending`). Supersedes the "use `before-hints`" advice of 2026-09-24 — the slot is now `after-hints`. Verify with a delayed request and a per-frame position sample, not a screenshot of the settled page.
