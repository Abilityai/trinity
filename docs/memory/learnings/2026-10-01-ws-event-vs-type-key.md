## 2026-10-01 — pitfall — A `/ws` broadcast must carry the key its consumer dispatches on (`event` vs `type`)
**Context**: #3109. `stores/network.js` (Dashboard, Timeline) dispatches on `data.type`; `utils/websocket.js` (agents store) switches on `data.event`. `agent_created` and `agent_deleted` sent only `event`, so the dashboard never heard a new agent (it waited for the 30 s poll) and its `agent_deleted` branch sat dead, unnoticed, while `agent_started`/`agent_stopped` worked because they send both. The dead branch also read `agent_name` off the envelope, where the name never was.
**Lesson**: Two frontend dispatchers read two different keys off the same stream, so an agent lifecycle broadcast sends `event` AND `type` with the same value, and a handler reads the payload from where the producer puts it (`data.data.name`). A new branch in a dispatcher is only live if a test feeds it the producer's real envelope. `tests/unit/test_3109_agent_ws_type.py` guards the four lifecycle events by AST; extend its `LIFECYCLE` set when a dispatcher gains a new `agent_*` case, rather than adding the case alone.
