## 2026-11-25 — pitfall — A rule keyed on what the old container carried is blind on the rebuild-from-nothing path
**Context**: trinity-enterprise#1279. Keeping a working-branch agent off the platform PAT when its repo stops being covered was first written as `carried_flag and not _broker ...` in `lifecycle._apply_git_env_from_db`. The config-drift recreate carries the old env, so it passed every test. `recreate_missing_container` (`pat_gate="effective"`) starts from an empty dict, so `carried_flag` is always False there, and the same agent rebuilt after container loss got the platform PAT on its working branch (uncovered repo) or on a still-covered repo (`coverage=None`, a transient provider error). An independent review found it; no test covered the effective path.
**Lesson**: Any env rule in `_apply_git_env_from_db` that reads the carried env (`carried_flag`, `env_vars.get("GITHUB_PAT")`, `GITHUB_REPO`) must state what it does when there is nothing carried, and the test file must run it with `pat_gate="effective"` and `env = {}`. On that path the old mode is unknowable, so pick the answer that never hands out a wider credential and pin it with a test. This is the 2026-07-23 "env assembled at several seams" class one level down: the seam was the same function, called with an input that cannot carry the signal.
