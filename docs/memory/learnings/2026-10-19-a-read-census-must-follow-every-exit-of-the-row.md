## 2026-10-19 — pitfall — A read-side census keyed on accessor call sites misses the exits that never call an accessor
**Context**: trinity-enterprise#780, `tests/unit/test_ent715_queue_person_fields.py` §7. The first census classified every call to a row-returning queue accessor (55 call sites in 45 functions across 10 modules) and looked complete. An adversarial review found three exits it could not see. The ask sink hands every ended row to registered ending observers, so a third observer forwarding `event.rows` would pass. The data module re-exports the table object (`_queue_db.operator_queue`). And a `db/` module that joins the table could feed a new accessor the census never followed. Two entries were also labelled `internal` / `agent` where a deliberate, ruled exception applied.
**Lesson**: A census of where a row can go enumerates every exit, not one spelling of it: accessor calls, callbacks registered with the sink (`register_*_observer`, decorators included), every import, attribute and SQL-text spelling of the table, and the data-layer modules that query it themselves. Pin each list both ways. Give a deliberate exception its own class that names the field and the ruling, never a generic "internal". Prove each detector with a meta-test of the spellings it must catch, and before reading a surviving mutant as a blind guard, check the mutant changed code rather than a docstring.
