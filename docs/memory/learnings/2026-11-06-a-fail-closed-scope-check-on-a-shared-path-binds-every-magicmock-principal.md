## 2026-11-06 — pitfall — A fail-closed scope check added to a shared path binds every MagicMock principal in the harnesses that call it
**Context**: trinity-enterprise#591. The template-source bound runs inside `crud.create_agent_internal` and, per the #2323 rule, bounds every principal whose `mcp_scope` is outside `{None, "user", "system"}`. The create harnesses (`test_1484`, `test_1759`, `test_fork_to_own`) build their user as a bare `MagicMock()`, whose `mcp_scope` is an auto-attribute — an unknown scope — and their mocked `database` answers the setting read with another MagicMock, which the bound reads as a damaged row (bounded to nothing). 104 creates across three files turned into `template_source_not_allowed` with no product change behind it.
**Lesson**: (1) When a fail-closed principal check lands on a path many harnesses drive, fix the harness users (`u.mcp_scope = None` for a person), never the check: weakening "unknown scope → bounded" to accommodate a stand-in reopens the #2323 class. (2) Judge the principal BEFORE any read the check needs, so a person's create never touches the setting: then only the harnesses whose user is genuinely ambiguous break, and they break loudly. (3) Count the affected files before choosing between "fix fixtures" and "change the rule"; here it was three builders and one line each.
