## 2026-11-26 — pitfall — A producer that stamps an email and no user id is rated a visitor
**Context**: abilityai/trinity-enterprise#1392. A room turn carried `source_user_email` and no `source_user_id`, so `turn_tier_service._rate` fell through to `share / visitor` and a person the agent is only shared with got the shell through a room. The Workspace had the same defect a month earlier (found testing #3778). The voice tool call sent no execution id at all.
**Lesson**: the turn-tier rule's fall-through for a row with no user id is the most permissive share answer (`visitor`, which `visitor_shell` gives the shell by default). Every new producer of an execution row must name its person: `source_user_id` for a platform principal, `turn_origin_user_id` for an agent's key, or a channel listed in `_PERSON_EMAIL_CHANNELS` when the platform verified the email. When adding a `triggered_by` or `source_channel`, add a row for it to the turn-tier tests and check what a shared person's turn rates as. A dispatch that skips `execute_task` has no row, and the agent treats a turn with no execution id as not the platform's.
