## 2026-09-30 — pitfall — A limiter on a route refuses everything that route carries, and a shared bucket lets its least-trusted drawer decide who sees the rest
**Context**: trinity-enterprise#676, plan review. The issue asked for the Workspace role-card route to take the `agent_objectives_read:{name}` key of `GET /api/agents/{name}/objectives`, so "one key bounds both doors to the container fan-out", and to return 429 under it. Both independent plan reviewers found the same thing: that route serves the role, the readiness stamp and the owner's flip control as well as the objectives, and the agent's own `get_objectives` tool draws on the same bucket. An agent polling its objectives would have blanked every viewer's card and hidden the control its owner uses on it. In the other direction any roster member could starve the agent's tool, because every other portal limiter is keyed per viewer and this one is not. The Workspace also rendered a failed role read as nothing, which reads as "this agent has no role". This is the 2026-08-26 floored-resource class (the loser of a shared limit sees "no data") arriving through a route instead of a probe.
**Lesson**: Before putting a limiter on a route, list what else that route returns, and refuse the limited resource, not the door. Use `rate_limiter.check`, leave the expensive part out, and name why in the payload (`objectives_error: objectives_rate_limited`); the rest of the response still answers. Before sharing a bucket between doors, list every principal that can spend it (including the agent itself through MCP) and say what each loser sees. Put a per-caller cap in front of the shared key, checked first, so a refused caller spends nothing from it; the order is load-bearing and gets a test (one viewer past their cap, then the other door still has its full remainder). Spell the key, limit and window once in a leaf both routers call, and prove the sharing behaviourally by exhausting one door and asking the other. Spend the token where the expensive part starts, not at the door: pass the builder a required check it calls just before the fan-out (a card that stops earlier — no role, a stopped agent — must spend nothing), and never default it to "admitted", which is an unbounded door for the next caller. The PR review found the first version spending a token on every Info-tab open, fan-out or not.
