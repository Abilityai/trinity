## 2026-10-12 — pitfall — a capability's owner bound must live in ONE helper, not in each path that honours the grant
**Context**: abilityai/trinity#3346 (trinity-enterprise#629 × #596/#164). `skills.manage` is honoured on two paths: the skills routes (`dependencies.get_skill_managed_agent_by_name`) and the files tab (`files._may_reach_for_path`). A review asked for the owner bound on the files path; it was added there only, so on an admin-owned install the skills routes still admitted another user's agent — `can_user_share_agent` short-circuits True for `role == "admin"`, and an agent key carries its owner's role.
**Lesson**: when a grant is honoured on more than one path, put its bound (grant check → `owner_owns_agent` → record) in one helper every path calls, and test each path with an agent owned by ANOTHER user under an admin owner. `can_user_share_agent` / `can_user_access_agent` are never an owner bound for an agent principal.
