## 2026-09-22 — pitfall — Awaiting a fire-and-forget recorder is necessary, not sufficient: `(tool, index-after-length)` is a position, and a position is not an identity
**Context**: #2952 — `src/mcp-server/src/access-wiring.test.ts`, the two `#2807:` transport cases PR #2855 added; CI run 35730033664 attempt 1 on PR #2936 (a PR touching nothing near the loop tools) failed `#2807: a refused loop start is audited as a refusal` with `the refusal was audited as a success: {"tool":"run_agent_loop","duration_ms":1,"success":true}`, and the same suite failed 2 of 2 full-suite runs on `dev` alone while the file alone passed 3 of 3. The 2026-09-16 entry for #2807 already said item (3): *a fire-and-forget POST can land after the client holds its result; a transport test awaits the recorder with a timeout or it flakes.* The test DID await — `auditRowFor(tool, after)` polled for the first `run_agent_loop` row at index ≥ `after`, where `after` was `auditRows.length` sampled at the top of the test. The previous test never awaited its own row (tests 1–3 read only the envelope), so under a busy host its late `success: true` row was the first row past the sample, and the finder returned it. The sibling `deny then allow on ONE session` case then chained: test 4's own refused row arrived during test 5, so `first` matched by coincidence and `second` was test 5's own refusal — `the permitted call inherited a stale refusal`. Deterministic on any host once the stub records the row 50 ms late; that perturbation is the mutation evidence in the fix PR. A second instance of the same class hides in plain sight: `audit-denial.test.ts` is deterministic only because `postAudit` calls `fetch` before its first `await`, so its synchronous `globalThis.fetch` stub has the row in `rows` before the wrapped call resolves — an undocumented property that a `withAudit` change (#2926) must not break, and that a real transport never had.
**Lesson**: A recorder fed by a fire-and-forget side channel needs **position + identity**, never position alone. (1) Every call made through the harness drains ITS OWN row before returning (`call()` → `{ out, row }`), with the row's index captured as a call counter inside the helper — then every earlier row has landed by construction when the next call starts, and `reset()` stays synchronous. (2) Give the row an identity the stub can echo: the production row copies `key_name` from the validate response and the bearer is forwarded unchanged, so a per-session bearer (`${KEY}-${name}`) echoed back as `key_name` lets the finder assert `row.mcp_key_name === key` with zero production change — "no discriminator on the row" is true per call but false per session, check what the stub controls before concluding a marker needs `audit.ts`. (3) Drain BEFORE the parse: a FastMCP `isError` text throws at `JSON.parse`, and a drain placed after it is skipped while the catch-path row is still in flight — the race back. (4) Turn the silent assumption into a loud precondition: `assert.equal(auditRows.length, calls)` at the top of every call names the two real causes (the row count per call changed in `audit.ts`, or a call bypassed the helper); a one-row-per-call change breaks the file on purpose. (5) Never put the guard in a `before`/`after` hook — an assertion thrown there exits 1 with `failureType: 'hookFailed'` but the summary still prints `# fail 0`, invisible to any `^# (tests|pass|fail)` grep; a real subtest failure is the only shape a count-based gate sees. (6) Cross-check with optional chaining (`row?.details?.tool`) so a malformed row is an `AssertionError` with the row dumped, not a `TypeError`. The failure direction after the fix is stricter, not looser: a dropped row now reds the cases that used to be blind to it, and a row from the wrong tool or session is refused with the row printed rather than skipped over.
