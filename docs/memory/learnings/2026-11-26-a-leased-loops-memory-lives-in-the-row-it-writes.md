## 2026-11-26 — pitfall — A leased loop that remembers "what I said last time" in a module global decides wrongly after every restart, lease move and lease round-trip
**Context**: #4778, `services/managed_hooks_check_service.py` (built in #4743). The fleet pass keeps one alert naming the agents that skip the managed hooks, and an agent that stops answering must stay named only if the alert already names it. "Already names it" was a module global, `_last_named`, starting `None`. The pass runs inside a leader-leased cycle that starts in every uvicorn worker, so the global had three wrong states: `None` after a restart or in a worker that just took the lease (given the most cautious meaning, "any silent agent holds the alert", so one stopped container kept a fixed fleet's alert open); the set of an old term in a worker that lost and regained the lease; and several disagreeing copies when the lease fails open. The original tests reset the global to `None` in the fixture and asserted the cautious branch, so the restart defect was pinned as designed behaviour.
**Lesson**: a loop gated by a lease has no memory of its own. Whatever one pass must know about the last pass is read from the durable thing the pass writes (here the alert's pending row, `context.agents`), on every pass and right before the decision, never from process state: grep a leased service for `global` and module-level `Optional[...] = None` state before approving it. Give "no row" and "row I cannot read" different answers (nobody named, versus could not tell), and return them as two values so the unreadable case cannot collapse into either the empty set or "everyone". A display payload that becomes control state this way needs a round-trip test (the real writer, then the real reader), because a later reshaping of the payload otherwise sends the reader to its "could not tell" branch without a red test. And a fixture that resets process state before each test is testing the first pass after a restart every time; write the test that starts from a row another worker wrote.
