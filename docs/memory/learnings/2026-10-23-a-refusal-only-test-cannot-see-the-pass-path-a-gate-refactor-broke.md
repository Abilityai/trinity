## 2026-10-23 — pitfall — A refusal-only test cannot see the pass path a gate refactor broke, and since ent#629 a sibling test through the access dependency may never reach the gate
**Context**: trinity-enterprise#840, converting nine modules' hand-copied agent-key self-gates to `dependencies.assert_own_agent`. Two blind spots surfaced. (1) `agent_files.share_agent_file` spelled its gate `actor_agent = getattr(current_user, "agent_name", None)` / `if actor_agent and actor_agent != agent_name: raise`, and `actor_agent` was read again further down (`created_by=actor_agent or …`). Replacing the two lines with the helper deleted the binding; the new census-driven sibling test stayed green (the gate raises before the read), and only `test_ent549`'s pass-path calls caught the `NameError`. (2) A sibling test written before ent#629 — agent-a's key reading agent-b through a `TestClient`, with no edge between them — stayed green with the self-gate line deleted: `AuthorizedAgentByName` now 404s an agent key outside its reach, so that sibling is refused by the dependency before the handler's gate runs, while the test's docstring still claims the gate is the only thing refusing it.
**Lesson**: When an inline check becomes a helper call, grep the function for every name the removed lines bound before deleting them, and run the route's pass path (its own key, a person), not just the refusal — a symtable pass over the changed modules finds an unbound read in seconds. A test that proves a handler-level agent self-gate must reach the handler: call the handler directly, or use a sibling INSIDE the caller's reach (a permission-edge target or an agent it spawned). An out-of-reach sibling now proves the access dependency, not the gate. Mutate the gate line and watch which test goes red.
