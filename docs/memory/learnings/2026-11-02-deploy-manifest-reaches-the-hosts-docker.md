## 2026-11-02 — pitfall — A unit test that drives `deploy_manifest` reaches the host's Docker unless `start_all_agents` is stubbed
**Context**: trinity-enterprise#871. `tests/unit/_ent695_world.py` fakes Docker at its read seams and gives the create seam a stand-in, but create mode then calls `system_service.start_all_agents`, which is real. A test over that world looks hermetic, stays green, and on any machine with a Docker daemon creates or recreates a real `agent-<system>-<member>` container with a workspace volume. If the daemon holds a container of that name it is stopped and replaced. `test_ent1030_gates.py` did this on every `pytest unit`, and a new test file copied the shape and did it again, surfacing only as a hang on `container.stop`.
**Lesson**: a fixture that drives `deploy_manifest` stubs `start_all_agents` in the fixture, not per test (`test_ent695_create_mode_golden.py` is the model). To check a suite is hermetic, point `DOCKER_HOST` at a logging fake API and read the log: a green run proves nothing, because the code swallows a start failure into a warning. Never run such a test first against the real daemon: `DOCKER_HOST=tcp://127.0.0.1:1` costs nothing.
